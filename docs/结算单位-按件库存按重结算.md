# 结算单位改造方案（白话版）

厂里记账、领料往往按「件 / 米 / 张」；跟供应商结账有时按「公斤」等另一套单位。

以前系统默认：**库存怎么记，钱就怎么算**。铸件、管材等「库存一件、按秤重结账」对不上。

**结算单位**就是专门管「跟供应商算钱用哪个单位」，跟厂里库存记账分开。

| 项         | 内容                                                                |
| ---------- | ------------------------------------------------------------------- |
| 适用范围   | 物料主数据、采购订单计价、收货/入库/采购退货结算数量、采购结算单    |
| 典型物料   | 铸件毛坯：库存/采购=件，结算=kg；管材：库存=米，结算=kg             |
| 低值易耗   | 仍用「领料属性」，与结算单位无关                                    |
| 主数据界面 | **单位管理 TAB**：主单位 + 辅助单位（业务角色）；底层仍是三口径字段 |

---

## 界面怎么配（单位管理 TAB）

主数据不再在基本信息里并排三个单位下拉，改为独立 **「单位管理」TAB**：

| 界面概念                | 白话                         | 底层字段                              |
| ----------------------- | ---------------------------- | ------------------------------------- |
| 主单位（基本单位）      | 仓库记账、领料、出库用这个   | `inventoryUnit`                       |
| 辅助单位 + 角色「采购」 | 跟供应商下单、点货件数用这个 | `purchaseUnit`（≠ 主单位时 = 双单位） |
| 辅助单位 + 角色「结算」 | 跟供应商算钱用这个           | `settleUnit`                          |
| 不配辅助 / 不勾角色     | 该角色跟主单位相同           | 结算空 = 不启用                       |

规则（须守住）：

- 主单位有且仅有一个
- 「采购」「结算」角色各最多挂一个辅助单位
- 「按批次覆盖」：默认换算率仅估算，入库/过磅实填为准
- 「固定」换算：本版只存配置，单据暂不自动折算
- 销售 / 生产 / 发料角色：界面预留，本版未开放

系统自己判断入库要填哪些数：

- 有采购辅助单位 → 入库要先填「到货件数」，再填库存数量
- 有结算辅助单位 → 入库还要再填「结算数量」（实重等）
- 只有主单位 → 入库只填一个数量

TAB 内灰字提示见 `src/utils/unitCaliber.js`。

主数据相关字段：

| 字段                 | 说明                                                                           |
| -------------------- | ------------------------------------------------------------------------------ |
| `settleUnit`         | 结算单位；空或不填 = 不启用                                                    |
| `settleConvertType`  | 本版固定为浮动实填（`floating`）                                               |
| `standardUnitWeight` | 可选标准单重（可来自结算辅助单位的默认换算率），仅开单估算，**不参与最终结算** |
| `auxUnits`           | 单位 TAB 的辅助单位列表（回显用）；与扁平字段同时保存                          |

校验：结算若启用，须与主单位不同。

演示料：`WL-CAST-BLANK-PUMP-01` 泵体铸件毛坯（件 / kg）。

## 和「可变长 / 双单位」的关系

两件事互不替代，可以叠在一起：

```text
只双单位：买「根」，库存记「米」——钱仍可按库存量×单价
只结算：买「件」，库存也「件」，结账按「kg」——钱按结算数量×单价
两者都有：买「张」、库存「㎡」、结账「kg」——入库字段最多
```

厂内领料、出库：**只认主单位（库存）**，不要求填结算数量。

## 单据上怎么走

```text
主数据单位 TAB（主单位 / 采购角色 / 结算角色）
  → 保存时推导 inventoryUnit / purchaseUnit / settleUnit
  → 采购订单（有结算单位时可估预计结算量；单价按结算单位理解）
  → 收货 / 入库（有结算单位则必填结算数量；库存仍按库存单位入账）
  → 采购结算（金额 = 结算数量 × 单价）

厂内出库 / 领料：只用库存单位，不碰结算单位
```

1. **主数据**：在单位 TAB 配主单位与辅助单位；结算默认换算率只用于开单估算，**最终结账以实填结算数量为准**。
2. **采购订单**：有结算单位时，预计结算量可按「件数 × 标准单重」估；单价按结算单位理解。
3. **入库 / 收货**：有结算单位则必填结算数量（如过磅实重）；库存数量仍按库存单位入账。
4. **采购结算**：有结算单位时，金额 = **结算数量 × 单价**（不是库存件数 × 单价）。
5. **出库 / 领料**：不碰结算单位。

计价规则集中在 `src/utils/settleUnit.js`：有结算单位 → 用 `settleQty`；否则用采购/库存数量。

## 入库界面原则

- **缺什么填什么**：该双单位才出「到货件数」；该结算才出「结算数量」。
- 不做「型材 / 板材 / 通用」三选一。
- 板材「长×宽」是可选辅助（功能参数「下料/订货尺寸辅助 → 面积换算」，默认开；关则不显示），不是第三套单位逻辑；仅库存单位为㎡且开启时出现。
- 列表上数量与单位同列展示（如 `55.5 kg`），避免数量、单位拆两列。

## 本版明确不做

- 小程序采购双数量
- 「固定换算」结算（件永远 × 固定系数自动结账）及单据侧自动折算
- 销售 / 生产 / 发料角色真正驱动单据单位
- 财务应付凭证对接
