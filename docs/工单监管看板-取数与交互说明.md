# 工单监管看板 — 取数逻辑说明（给开发）

> 聚合实现：`src/utils/workOrderMonitorDashboard.js`（`buildWorkOrderMonitorDashboard`）  
> 对接原则：**换接口，不改口径**。下文以「业务口径」为准。

---

## 1. 数据源

| 数据         | 用途                             | 关键字段（对齐现网）                                                                    |
| ------------ | -------------------------------- | --------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------- |
| 生产工单     | 工单 KPI、执行列表、工序节点     | `id/orderNo/status/workCenter/planQty/scheduleQty/planDateRange/productName/productCode | materialCode/specModel/material/processes[]/scheduleBatches[]/updatedAt/createdAt` |
| 组装工单     | 同上                             | 同上；看板内标记类型=`组装工单`                                                         |
| 工序移动任务 | 任务执行 KPI、工序节点、工人闲忙 | 含 `createdAt/reportedGoodQty/reportedBadQty/reportDuration/...`                        |
| 工时管理     | 任务执行 · 工时                  | `workOrderId/workOrderNo/accountHours/reportDate`                                       |
| 领料申请     | 物料消耗 · 已领取 / 待出库       | `workOrderCode/lines[]/lineCount/outboundStatus/createdAt`                              |
| 库存扣减     | 物料消耗 · 已消耗                | `workOrderId/workOrderNo/status/lines[]/confirmedAt`                                    |
| 员工小组     | 右侧小组                         | `id/name/status/leaderName/workers[]/workCenter`                                        |

合并工单集合后，先按 **工单类型、工作中心** 过滤，得到集合 `all`，后续 KPI/列表/工序统计均基于 `all`（工人任务另说）。

---

## 2. 筛选参数与作用范围

| 参数         | 取值                                  | 作用                                                                                                                                              |
| ------------ | ------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| `period`     | 本日 / 本周 / 本月                    | 影响：工单总数、工单已完成、任务数/良不良/工时、物料消耗；**不**过滤待下发/进行中快照，也**不**过滤任务执行里的已报工/在制/待领取（工序节点快照） |
| `woType`     | 全部 / 生产 / 组装                    | 过滤 `all`                                                                                                                                        |
| `workCenter` | 全部 / 具体值                         | 过滤 `all`（匹配工单 `workCenter`）                                                                                                               |
| `listStatus` | 进行中(默认) / 待下发 / 已完成 / 全部 | **只**过滤工单执行列表，不影响 KPI                                                                                                                |

### 2.1 周期时间窗

- 本日：当天
- 本周：自然周起止（dayjs `startOf/endOf('week')`）
- 本月：自然月起止
- 判断：取日期串前 10 位 `YYYY-MM-DD`，落在 `[start, end]` 闭区间

### 2.2 工单状态桶（核心）

```
待下发                    → pending
已完成 / 完成             → done
终止                      → 不计 KPI、不算进行中
其余（含 已下发/执行中/暂停）→ running（进行中）
```

列表「进行中」= `bucket === running`。

## 3. KPI 取数

### 3.1 工单数量

基于过滤后的 `all`：

| 指标     | 公式                                                                   |
| -------- | ---------------------------------------------------------------------- |
| 工单总数 | `count(createdAt ∈ period)` — **按时段创建**，不限状态（含终止）       |
| 待下发   | `count(bucket=pending)` — **当前快照**                                 |
| 进行中   | `count(bucket=running)` — **当前快照**                                 |
| 已完成   | `count(bucket=done 且 (updatedAt\|\|createdAt) ∈ period)` — **按时段** |

### 3.2 任务执行（原「报工数量 + 工序状态」合并）

界面一块展示 7 项：

| 指标     | 口径                                                                                           |
| -------- | ---------------------------------------------------------------------------------------------- |
| 计划数   | 周期内**创建**的工单 `Σ planQty`（与工单总数同一批）                                           |
| 排产数   | 周期内**创建**的工单 `Σ scheduleQty`                                                           |
| 任务数   | 周期内**生成**的移动任务条数（过类型/中心；忽略 terminate 隐藏）                               |
| 已报工   | 当前 `all` 工单工艺路线**节点**归桶：`已报工`/`已完成`（**快照**，不受周期）                   |
| 在制     | 节点快照：`执行中`/`待开始`/`待报工`/`待分发`                                                  |
| 待领取   | 节点快照：`待领取`                                                                             |
| 良品数   | 周期内生成任务 → **按工单取 max(reportedGoodQty)** 再求和                                      |
| 不良品数 | 周期内生成任务 → **按工单取 max(不良)** 再求和                                                 |
| 工时     | 优先工时管理 `accountHours`（关联工单且日期∈周期）；否则回退任务 `reportDuration` 合计（小时） |

现网约定：工人提交一次报工 = 该工序任务完成（不要求凑满排产数）。暂停节点不计入已报工/在制/待领取。

### 3.3 物料消耗

关联当前筛选工单；周期看申请/扣减时间。  
**按物料行「项数」统计**（单位不同，不可把数量直接相加）：

| 指标   | 口径                                                               |
| ------ | ------------------------------------------------------------------ |
| 已领取 | 领料申请 `outboundStatus=已出库` 的 **物料行数**                   |
| 待出库 | 领料申请 `outboundStatus=待出库` 的 **物料行数**                   |
| 已消耗 | 库存扣减单状态=成功/部分成功 中，可扣减且非「无需扣减」的 **行数** |

## 4. 工序节点取数（工艺路线）

### 4.1 节点怎么来

1. 优先用工单 `processes[]`
2. 每道工序用 `listMobileTasksForWorkOrder(woId)` 匹配任务（同名/`processId`；优先 `执行中` > `已完成` > 忙碌态 > 任意）
3. 无 `processes` 时：按任务 `processName` 去重，用 `processSeq` 作 `stepNo`
4. **同 `stepNo` = 并行**；按 `stepNo` 升序串成路线

### 4.2 节点展示态（优先级）

以任务为准，无任务再看工序字段：

1. `controlStatus=暂停` 且未完成 → `暂停`
2. `taskStatus=已完成` → `已报工`
3. `reportedFinishedQty>0` 或 `reportedGoodQty>0` → `已报工`
4. `执行中` / `待领取` / `待报工|待开始|待分发` → 原样
5. 兜底：`taskStatus` 或工序 `status` 或 `待报工`

### 4.3 节点数量

| 展示 | 取数（有值优先，取第一个有效正数/有限数）                                              |
| ---- | -------------------------------------------------------------------------------------- |
| 计划 | 工序 `planQty/scheduleQty` → 任务 `expectedQty/targetQty` → 工单 `scheduleQty/planQty` |
| 良   | 任务 `reportedGoodQty` → 工序 `reportedGoodQty/goodQty`                                |
| 不良 | 任务 `reportedBadQty/reportedDefectQty/badQty` → 工序对应字段                          |

忽略 `hiddenByTerminate=true` 的任务。

## 5. 工单执行列表取数

### 5.1 行集合

```
rows = all
  .filter(matchListStatus)
  .sort(updatedAt|createdAt 降序)
  .slice(分页)
```

### 5.2 行字段映射

| 展示      | 取数                                             |
| --------- | ------------------------------------------------ |
| 工单编号  | `orderNo \|\| workOrderNo \|\| id`               |
| 产品名称  | `productName \|\| itemName`                      |
| 产品编号  | `productCode \|\| materialCode`                  |
| 规格型号  | `specModel \|\| spec`                            |
| 材质      | `material`                                       |
| 类型      | 生产工单 / 组装工单                              |
| 状态      | `status`                                         |
| 工作中心  | `workCenter`                                     |
| 计划/排产 | `planQty` / `scheduleQty`                        |
| 计划日期  | `planDateRange[0] ~ [1]`（或 planStart/planEnd） |
| 工艺路线  | §4 `routeSteps`                                  |

### 5.3 批次标签

存在 `scheduleBatches`，且（长度>1 **或** 存在 `status≠待下发` 的批次）时：

- 优先用已下发批次的 `batchNo`，展示 `批次#1/2`
- 否则 `批次`

### 5.4 逾期

```
status ∉ {已完成, 完成, 终止}
且 计划结束日 < 今天(按日)
→ overdue = true
```

计划结束日 = `planDateRange[1] \|\| planEndDate`。

## 6. 工人接单取数

### 6.1 任务忙碌集合

```
BUSY = { 待报工, 待开始, 执行中 }
```

小组进行中任务额外含：`待分发`。

人员匹配：`claimedBy \|\| executor` 等于姓名。

### 6.2 工人小组

数据：`employeeGroupState` 中 `status` 空或 `启用`。

| 判定             | 规则                                                                                          |
| ---------------- | --------------------------------------------------------------------------------------------- |
| 小组进行中任务   | 任务 `groupId/groupName` 命中，或 `resourceType=工人小组` 且执行人=组长，且状态∈BUSY∪{待分发} |
| 组长已接小组任务 | 存在上述任务，且 `claimedBy/executor=组长` 或状态=`待分发`                                    |
| 整组忙碌         | 有小组进行中任务 **或** 任一组员个人忙碌                                                      |
| 组员「组内待命」 | 组长已接小组任务，且该组员本人无 BUSY 个人任务                                                |
| 组员「忙碌」     | 本人有 BUSY 任务（可与小组任务并存）                                                          |
| 空闲             | 非忙碌且非组内待命                                                                            |

组成员 = `leaderName` ∪ `workers[].name`（去重）。

### 6.3 单工人

**独立于小组列表**，可与组内同一人同时出现。

名单来源（去重）：

1. 任务满足「个人任务」：`resourceType≠工人小组` 且无 `groupId/groupName`，取其 `claimedBy/executor/executors/claimTargets`
2. 工单工序 `resourceType≠工人小组`（默认工人）的 `executors`

闲忙：**只看个人任务** 是否落在 BUSY。

副文案：当前任务优先 `执行中`，否则任意 BUSY → `工序名 · 工单号`。

### 6.4 顶部忙/闲统计

对人名去重：

| 统计 | 口径                                                           |
| ---- | -------------------------------------------------------------- |
| 忙   | 小组内 `statusTone=busy` ∪ 单工人 `busy`（按人名去重）         |
| 待命 | 小组内 `statusTone=standby` 人数（组内待命）                   |
| 闲   | `总人数 - 忙 - 待命`（总人数=小组出现过的人名 ∪ 单工人，去重） |

## 8. 口径易错点（联调必看）

1. **进行中 ≠ 仅执行中**：含已下发、暂停。
2. **周期**：影响工单总数（按创建）、已完成（按完结时间）、任务数/良不良/工时、物料消耗；**不影响**待下发/进行中快照，也不影响任务执行里的已报工/在制/待领取。
3. **工序完成**：有报工量或任务已完成即「已报工」，不跟排产数比大小。
4. **在制**：含极简下发即执行中/待开始，不是待领取。
5. **任务执行合并块**：任务数/良不良/工时看周期；已报工/在制/待领取是工序节点快照。良/不良按工单取 max。
6. **物料消耗按项数**：已领取/待出库/已消耗都是物料行条数，不按数量加总（单位不一致）。
7. **单工人与小组**：两套列表；入组的人仍可出现在单工人（有个人任务时）。
8. **组内待命 ≠ 空闲**：组长接了小组活、组员自己没领任务。

### 工单列表分页（高度装箱，固定 6 格）

实现：`packMonitorListPages` + `resolveMonitorRowHeightUnits`（`workOrderMonitorDashboard.js`），列表区用 flex 按格数均分高度。

| 规则             | 说明                                                                                                             |
| ---------------- | ---------------------------------------------------------------------------------------------------------------- |
| 一页容量         | 固定 **6 格**（`MONITOR_PAGE_SLOT_UNITS`）                                                                       |
| 串行工单         | 占 **1 格** → 全串行时一页 **6 单**，卡片高度/间距随容器均分                                                     |
| 并行工单（默认） | 占 **2 格**；并行区默认只展示前 **4** 道（`MONITOR_PARALLEL_DEFAULT_VISIBLE`）→ 如 1 并行 + 4 串行 = **5 单/页** |
| 「展示全部」     | 展开后展示全部并行工序；在默认 2 格基础上，**每多展示一道并行工序 +1 格**，本页可容纳的其它工单相应减少          |
| 「收起」         | 回到默认 4 道 / 2 格                                                                                             |
| 串行工序盒子     | 同一条路线里，非并行步骤按内容正常高度，**不**被并行虚线框拉高                                                   |

后端按整页返回列表即可；装箱与展开属前端展示。并行展开状态不写后端。
