# 工单监管看板 — 取数与交互说明（给开发）

> 原型位置：`i-doms-web`  
> 入口：更多 → 看板管理 → 工单监管看板（**新浏览器标签**打开独立大屏页）  
> 核心文件：
>
> - 页面：`src/views/board/WorkOrderMonitorView.vue`
> - 聚合：`src/utils/workOrderMonitorDashboard.js`
> - 菜单：`src/config/menus.js`（`openInBrowserTab`）
> - 路由：`/board/work-order-monitor`（内嵌）、`/board/work-order-monitor/screen`（独立大屏，`meta.standalone`）

---

## 1. 页面结构

```
┌─ 顶栏：标题 | 轮播开关+秒数 | 更新时间 | 周期/类型/工作中心 | 刷新 | 全屏 ─┐
├─ KPI 三块：工单数量 | 报工数量 | 工序状态 ──────────────────────────────┤
├─ 工单执行情况（左，主列表分页+轮播）──┬─ 工人接单情况（右，分页+轮播）──┤
└────────────────────────────────────┴────────────────────────────────┘
```

## 3. 筛选条件

| 筛选项                 | 值                                     | 作用范围                                                                            |
| ---------------------- | -------------------------------------- | ----------------------------------------------------------------------------------- |
| 统计周期               | 本日 / 本周 / 本月                     | **仅**影响：工单 KPI「已完成」、报工 KPI；**不影响**待下发/进行中快照、列表默认数据 |
| 工单类型               | 全部 / 生产 / 组装                     | 全局过滤                                                                            |
| 工作中心               | 全部 / 具体中心                        | 全局过滤                                                                            |
| 列表状态（工单执行区） | 进行中（默认）/ 待下发 / 已完成 / 全部 | 仅工单列表                                                                          |

### 3.1 工单状态桶 `mapWoBucket`

| 系统状态                                     | 桶                    |
| -------------------------------------------- | --------------------- |
| `待下发`                                     | pending               |
| `已下发` / `执行中` / `暂停`（及其它非终态） | **running（进行中）** |
| `已完成` / `完成`                            | done                  |
| `终止`                                       | 不计入 KPI            |

## 4. KPI 取数

### 4.1 工单数量

| 指标   | 口径                                                    |
| ------ | ------------------------------------------------------- |
| 待下发 | 当前快照，`bucket=pending`                              |
| 进行中 | 当前快照，`bucket=running`（含已下发/执行中/暂停）      |
| 已完成 | `bucket=done` **且** `updatedAt/createdAt` 落入统计周期 |

### 4.2 报工数量

按 `processReportState.records`：

- 过滤：`createdAt` ∈ 统计周期
- 若记录有 `workOrderId` / `workOrderNo`：必须属于当前类型+工作中心过滤后的工单集合
- 无工单关联：仅当类型=全部 **且** 工作中心=全部 时计入

| 指标     | 字段             |
| -------- | ---------------- |
| 笔数     | 记录条数         |
| 良品数   | `sum(goodQty)`   |
| 不良品数 | `sum(defectQty)` |

### 4.3 工序状态（当前筛选范围内全部工单的工序节点汇总）

现网约定：**工人提交一次报工 = 该工序任务完成**（不要求凑满排产数；无「部分报工未完工」）。

| KPI 展示 | 取数                                                                           |
| -------- | ------------------------------------------------------------------------------ |
| 已报工   | 工序节点 `已报工/已完成`（任务 `taskStatus=已完成`，或已有报工量）             |
| 在制     | 已到工人端/已指派，**尚未报工完成**：`执行中` / `待开始` / `待报工` / `待分发` |
| 待领取   | `待领取`（多人抢领）                                                           |

> 原型曾用「排队/未开工」命名，现已收敛为「在制」。`processQueue` 字段可忽略。

工序展示态优先级（`resolveProcessDisplayStatus`）：

1. 控制暂停 → `暂停`
2. 任务已完成 / 有报工量 → `已报工`
3. `执行中` / `待领取` / `待报工|待开始|待分发`

极简单人/单组下发后任务多直接进「今日报工」（`placement=todo`，状态常为执行中/待开始），计入 **在制**，不是待领取。

## 5. 工单执行情况

### 5.1 列表行字段

标题顺序（空字段不展示）：

`工单编号` → `批次标签?` → `产品名称` → `产品编号` → `规格型号` → `材质` → `类型Tag` → `状态Tag` → `逾期Tag?`

元信息：`工作中心` | `计划/排产` | `计划日期`

| 字段     | 取数                                                                         |
| -------- | ---------------------------------------------------------------------------- |
| 产品编号 | `productCode \|\| materialCode`                                              |
| 计划日期 | `planDateRange[0] ~ [1]`                                                     |
| 批次     | 有 `scheduleBatches` 且（多批 **或** 存在非「待下发」批次）→ 展示 `批次#1/2` |
| 逾期     | 计划结束日 &lt; 今天，且状态 ∉ {已完成, 完成, 终止}                          |

### 5.2 工艺路线

- 数据：`workOrder.processes` + 该单移动任务
- **同 `stepNo` = 并行**；按 `stepNo` 排序串成链，步间箭头连接
- 节点展示：工序名、状态、`计划 / 良 / 不良`
- 并行 &gt; 4 紧凑网格；大屏默认最多展示 **4** 个并行节点（不展开，避免滚动）
- 列表区 **禁止纵向滚动**：按可视高度算 `pageSize`（约 1～6），多页轮播

### 5.3 点击工单号

- 独立大屏页：`window.open` 工单列表（带 keyword）
- 内嵌页：系统内 `openTab` 跳转

## 6. 工人接单情况

分两块并行展示：**工人小组**、**单工人**。

### 6.1 忙碌判定

任务忙碌状态集合：`待报工` | `待开始` | `执行中`（另：小组任务含 `待分发`）

### 6.2 工人小组

数据：启用状态的 `employeeGroupState.groups`。

| 角色             | 逻辑                                                     |
| ---------------- | -------------------------------------------------------- |
| 整组忙碌         | 存在进行中小组任务，或任一组员忙碌                       |
| 组长已接小组任务 | 组长 → **忙碌**；组员无个人任务 → **组内待命**（非空闲） |
| 组员自己有任务   | 仍显示个人 **忙碌**                                      |

小组任务匹配：`groupId` / `groupName` / `resourceType=工人小组` 且执行人=组长。

### 6.3 单工人

- 来源：`resourceType≠工人小组` 且无 `groupId/groupName` 的任务执行人；以及工单工序 `resourceType=工人` 的 `executors`
- **不因入组而隐藏**：可与小组区同时出现
- 闲忙只看 **个人任务**

顶部统计：忙 / 待命 / 闲（人名去重）。

### 6.4 分页与轮播

- 内容项：`1 个小组卡 = 1 项`，`1 个单工人 = 1 项`（分区标题不计入 pageSize）
- `workerPageSize` 按右侧列表可视高度估算（约 2～5）
- 小组卡内最多展示 3 名成员，其余显示「等 N 人」，保证单卡高度稳定、列表无滚动条
- 底部简易分页：`共 X 项 · 当前页/总页`；与工单区共用轮播秒数自动翻页

## 7. 交互与大屏行为

| 能力     | 说明                                                                                           |
| -------- | ---------------------------------------------------------------------------------------------- |
| 打开方式 | 菜单 `openInBrowserTab` → `/board/work-order-monitor/screen` 新标签（无顶栏侧栏）              |
| 全屏     | Fullscreen API；失败则 CSS 伪全屏                                                              |
| 轮播     | 标题旁开关 + 秒/页（默认开、15 秒，范围 5～300）；`localStorage`：`i_doms_wo_monitor_carousel` |
| 轮播动作 | 同一 tick：工单页 +1（末页回 1）、工人页 +1（末页回 1）；仅 1 页则跳过                         |
| 自适应   | `ResizeObserver` 测列表高度 → 动态 `pageSize` / `workerPageSize`；字号 `clamp`                 |
| 刷新     | 手动刷新重算；改筛选项重置工单页码为 1                                                         |

## 8. 聚合 API 形态（对接建议）

前端一次拉齐或 BFF 一次返回均可，结构对齐：

```ts
{
  updatedAt: string
  kpis: {
    pending, running, done,          // 工单
    reportCount, goodQty, badQty,    // 报工
    processDone, processRunning, processClaim  // 工序
  }
  list: { total, page, pageSize, rows: WorkOrderRow[] }
  workers: {
    groups: GroupPanel[]
    individuals: PersonPanel[]
    busy, standby, idle, total
  }
}
```

查询参数建议：`period`、`woType`、`workCenter`、`listStatus`、`page`、`pageSize`。

工人区分页可前端切，也可后端分页（需稳定排序：忙优先 → 名称）。

## 10. 验收要点

1. 进行中列表含：已下发、执行中、暂停
2. 极简单执行人下发后的任务进「在制」，不是「待领取」
3. 一次报工后工序进「已报工」，即使数量 &lt; 排产
4. 分批下发显示批次标签；超计划日未完显示逾期
5. 右侧同时有小组与单工人；组长接单后组员为组内待命
6. 大屏无列表滚动条，靠轮播翻页；新标签独立打开可全屏挂电视
