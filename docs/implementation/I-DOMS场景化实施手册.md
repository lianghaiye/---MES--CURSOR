## 1. 怎么用这份手册

### 1.1 场景化要解决什么

离散制造企业数字化程度差异大。一次性上「订单到质量」全模块，失败率高。本方案主张：

> **先卖清一个老板听得懂、现场用得上的结果；再按组织成熟度往上加场景。**

### 1.2 谁读哪一段

| 角色     | 重点阅读                                                         |
| -------- | ---------------------------------------------------------------- |
| 售前     | §2 总览、§3 四维诊断、各场景「优势 + 话术」、§10 话术总表        |
| 实施     | 各场景「重点调研 → 对应功能 → 分步路径」+ 检查清单 + Excel 附件  |
| 双方对齐 | 每个场景写清：对客可见范围 / 系统背后要配什么 / 建议从哪一级切入 |

### 1.3 对外用语与系统能力（对内对照）

| 对外说法                                           | 系统能力（实施配置）                                                       | 对客是否强调                                   |
| -------------------------------------------------- | -------------------------------------------------------------------------- | ---------------------------------------------- |
| **快速报工**                                       | 小程序「工序报工 · 快速报工」和/或「登记产出（按工序）」；WEB 工序报工审核 | 是                                             |
| **任务报工**                                       | 工单下发 → 小程序待领/今日待报工；WEB 工序报工审核                         | 是                                             |
| **工资核算**                                       | 工时配置（产品/工序）+ 工时管理 + 工资核算；功能参数「工资推送模式」       | 是                                             |
| **领料 / 成品入库**                                | 领料管理、出库、入库；小程序领料/成品入库                                  | 是                                             |
| **库存管理**                                       | 仓库档案、出入库、库存明细等                                               | 场景四起对外讲                                 |
| **库存扣减 / 预扣确认**                            | 功能参数「库存扣减方式」+ 扣减记录菜单                                     | **否**（不写进场景卖点；权限与参数里配好即可） |
| **销售订单 / BOM / 计划排产 / 生产 / 采购 / 质量** | 对应顶栏模块                                                               | 场景四、五                                     |

> 库存扣减：企业明面上关心的是「领了料、入了库、账对得上」；扣减是系统把账算准的手段。售前不主动讲「扣减场景」，实施在角色权限与功能参数中关联开通。

## 2. 五场景总览与分步路径

### 2.1 场景一览

| 编码   | 场景名称（对外）                                                                      | 一句话价值                                  | 建议试点周期      |
| ------ | ------------------------------------------------------------------------------------- | ------------------------------------------- | ----------------- |
| **一** | 快速报工 + 工资核算                                                                   | 工人手机报工，主任审核，计件/计时工资算得出 | 1～2 周           |
| **二** | 快速报工 + 工资核算 + 领料 + 成品入库                                                 | 在一基础上，料出得去、成品进得来            | 2～4 周           |
| **三** | 任务报工 + 工资核算 + 领料 + 成品入库                                                 | 有工单/任务约束的产线闭环                   | 3～5 周           |
| **四** | 销售订单 + BOM 设计 + 计划排产 + 生产管理 + 任务报工 + 工资核算 + 库存管理 + 采购管理 | 从接单到采购、生产、库存一条链              | 6～10 周          |
| **五** | 场景四 + 质量管理                                                                     | 在四基础上把出厂质检、报废、质检模板管起来  | 在四之上 +2～4 周 |

### 2.2 推荐扩场景路径

```mermaid
flowchart LR
  S1[场景一<br/>快速报工+工资]
  S2[场景二<br/>+领料+成品入库]
  S3[场景三<br/>任务报工+领料入库]
  S4[场景四<br/>订单到采购]
  S5[场景五<br/>+质量管理]
  S1 --> S2
  S1 --> S3
  S2 --> S3
  S3 --> S4
  S4 --> S5
```

| 现状判断                                   | 建议切入                                    | 下一步             |
| ------------------------------------------ | ------------------------------------------- | ------------------ |
| 数据弱、人员少用信息系统、先要「工资算清」 | **场景一**                                  | 跑顺后再加二或三   |
| 已有简单出入库诉求，仍偏口头派工           | **场景二**                                  | 派工规范化后升三   |
| 已有工单/派工习惯，要产量与物料对齐        | **场景三**                                  | 再谈订单与采购升四 |
| 组织有计划/采购/仓管分工，主数据较齐       | 可直上 **场景四**（仍建议先小范围试点报工） | 质量诉求强再升五   |
| 客户/行业强制质检留痕                      | **场景五**（或四验收后立刻加质量包）        | —                  |

### 2.3 场景依赖（主数据视角）

| 场景 | 最低主数据                      | 业务单据                                |
| ---- | ------------------------------- | --------------------------------------- |
| 一   | 人员、产品、工艺工序、工价      | 报工单 → 工资                           |
| 二   | 一 + 仓库、常用物料             | 领料、成品入库                          |
| 三   | 二 + 工单/任务习惯              | 生产工单 → 任务报工                     |
| 四   | 三 + 客户/供应商、BOM、计划逻辑 | 销售订单 → 设计/计划 → 工单/采购 → 库存 |
| 五   | 四 + 质检模板/不良项            | 出厂质检、报废等                        |

## 3. 企业适配：四维诊断

> 选型不要只问「企业大不大」，要问：**组织怎么分工、这些职能要不要系统管、数据齐不齐、人接不接得住。**

### 3.1 维度一：组织架构

| 观察点     | 问法                                             | 对选型的含义                                                   |
| ---------- | ------------------------------------------------ | -------------------------------------------------------------- |
| 人数与班组 | 几个车间、几条产线、几班倒？                     | 人少也可上场景一；班组多更要手机报工                           |
| 管理层级   | 有无独立车间主任 / 计划员 / 仓管 / 采购 / 质检？ | 有专职 → 可配独立角色；无专职 → **一人多岗**，菜单合并到少数人 |
| 汇报关系   | 工资谁审、入库谁点头、采购谁批？                 | 决定审批流与工资推送模式                                       |

**实施动作**：画出「岗位—姓名—兼职」表，再映射系统角色（见 §9），避免按「理想组织」硬开一堆账号。

### 3.2 维度二：质检 / 采购 / 仓管——有人 ≠ 一定要上模块

再小的企业也有人管料、管买、管看质量，常见是老板娘兼仓管、技术兼质检。关键不是「有没有这个岗」，而是：

| 职能     | 需要系统化管理的信号                          | 暂时不必强推的信号                   |
| -------- | --------------------------------------------- | ------------------------------------ |
| **仓管** | 经常对不上账、成品/原料混放纠纷、要按单出入库 | 料少、口头清点够用、老板不看库存报表 |
| **采购** | 缺料频繁、供应商多、要按订单算需求            | 固定几家供应商、老板亲自买、无计划员 |
| **质检** | 客户要出厂报告、不良争议多、要留检记录        | 仅目视、无客户强制、无不良统计诉求   |

**话术**：「不是说你们没仓管才不上库存，而是看你们要不要**留痕、可对账、可追溯**。一人兼多职一样能用，账号少、菜单精简即可。」

### 3.3 维度三：数据基础

| 等级   | 表现                                         | 建议                                           |
| ------ | -------------------------------------------- | ---------------------------------------------- |
| **弱** | 无统一产品编码、工序口头叫法不一、库存靠本子 | **场景一**；先整理「产品+工序+工价」三张表     |
| **中** | Excel 有编码但不统一；有简单进出库表         | **场景二/三**；导入前做一轮清洗                |
| **强** | 编码唯一、BOM/工艺较完整、进出库有台账       | 可评估 **场景四/五**；仍建议试点产线先跑通报工 |

### 3.4 维度四：人员信息化认知

| 等级   | 表现                          | 建议                                                  |
| ------ | ----------------------------- | ----------------------------------------------------- |
| **弱** | 抵触手机填数、习惯纸质签字    | 场景一小范围试点；培训按「报一次工=算一笔钱」激励     |
| **中** | 会用微信/表格，用过简单进销存 | 场景二/三；强调比 Excel 少扯皮                        |
| **强** | 用过 ERP/MES，有关键用户      | 可谈场景四/五；注意对齐旧系统口径，忌承诺「一夜替换」 |

### 3.5 诊断结论怎么落地（售前一句话）

| 四维组合（简）             | 推荐               |
| -------------------------- | ------------------ |
| 数据弱 或 认知弱           | 场景一 → 再扩二/三 |
| 组织有仓管诉求、派工仍随意 | 场景二             |
| 已有派工/工单习惯          | 场景三             |
| 数据中强 + 有计划/采购分工 | 场景四             |
| 另有质量留痕刚需           | 场景五             |

## 4. 场景一：快速报工 + 工资核算

### 4.1 适合什么样的企业

- 最痛的是：**产量对不上、计件扯皮、月底算工资靠Excel熬夜**。
- 派工偏口头/临时，**暂不强求工单任务**。
- 组织上：有主任（或班组长）能审核即可；仓管/采购/质检可暂不进系统。
- 数据：至少能整理出「产品、工序名称、工价」。
- 认知：工人愿用手机报一次数。

### 4.2 场景优势

1. **结果可见快**：一周内能看到「报工—审核—工资」闭环。
2. **主数据门槛低**：不强制 BOM、销售订单、完整库存。
3. **一人多岗友好**：管理员兼主任即可，菜单少。
4. **为后面场景打地基**：产品/工序/工价是后续场景的共用底座。

### 4.3 重点调研内容 → 对应系统功能

| 调研问题                               | 要拿到的结论                                | 对应系统功能                                    |
| -------------------------------------- | ------------------------------------------- | ----------------------------------------------- |
| 现在怎么记产量？谁签字？               | 纸质/微信/表格；审核人是谁                  | 小程序快速报工；WEB 工序报工审核                |
| 按件数算工资还是按工时？次品怎么算钱？ | 计件/计时算法写清；不良是否计薪、按多少比例 | 产品/工序「工时配置」；不良品项；计薪口径确认表 |
| 工资何时算进账？审核能否改数量？       | 推送时机、调整是否覆盖                      | 功能参数「工资推送模式」；工时管理 / 工资核算   |
| 产品、工序叫法是否统一？               | 编码与工序名清单                            | 产品物料、工艺路线/工序配置                     |
| 试点范围？                             | 哪个车间、哪些人                            | 组织人员、角色、小程序账号                      |

### 4.4 分步实施路径

1. **启动会**：确认场景一只做「报工+工资」，书面砍掉库存/订单期望。
2. **口径会**：签《计薪口径确认表》。
3. **主数据**：导入人员、产品、工序、工价（先试点 3～5 个产品）。
4. **配置**：工资推送模式、审核角色、小程序入口。
5. **试运行**：选 1 条线 / 1 个班组，连续 3～5 个工作日。
6. **对账**：系统工资明细 vs 原 Excel，差异讲清再推广。
7. **验收**：工人会报、主任会审、财务/老板认可一版工资结果。

### 4.5 话术

- 「先不谈上全部系统。就一件事：**工人手机报工，月底工资有据可查。**」
- 「你们现在工序名要是不统一，工资永远对不齐——我们先帮你们把产品、工序、单价三张表定死。」
- 「仓管、采购、质检以后都能加；现在不上，是为了**两周内见效**，不是功能没有。」

### 4.6 MVP / 明确不做（本场景）

| 做                            | 不做（对客承诺）                                 |
| ----------------------------- | ------------------------------------------------ |
| 快速报工、审核、计件/计时工资 | 完整工单任务体系（可后续升场景三）               |
| 试点车间人员与工价            | 销售订单、BOM、计划、采购、质量管理              |
|                               | 对外不讲「库存扣减」；本场景默认不开放库存类菜单 |

## 5. 场景二：快速报工 + 工资核算 + 领料 + 成品入库

### 5.1 适合什么样的企业

- 场景一的痛点仍在，同时出现：**原料不知去向、成品入库靠吼、账实经常吵**。
- 派工仍可偏快速报工；**还不想上完整任务派工**。
- 组织：有人兼仓管即可；采购/质检仍可不进系统。
- 数据：仓库名单、常用物料、期初大概数量能盘出来。
- 认知：仓管愿意在手机或 WEB 点出入库。

### 5.2 场景优势

1. **产与料同时看见**：产量与领料、入库能对照，少扯皮。
2. **仍保持「快速」**：不强上复杂派工，适合临时任务多的小厂。
3. **库存能力可藏可露**：对客讲领料、入库；扣减口径在参数里配好。
4. **自然过渡到场景三**：习惯留痕后，再加任务约束阻力更小。

### 5.3 重点调研内容 → 对应系统功能

| 调研问题                       | 要拿到的结论       | 对应系统功能                                         |
| ------------------------------ | ------------------ | ---------------------------------------------------- |
| （含场景一全部调研）           | —                  | —                                                    |
| 领料谁发起、谁发料？要不要审？ | 角色与是否自动审核 | 领料管理；小程序领料；出库管理；自动审核参数         |
| 成品谁入库、按什么数量？       | 与报工数是否一致   | 成品入库；入库管理                                   |
| 几个仓？原料/成品是否分开？    | 仓库档案           | 仓库基础配置                                         |
| 账实差异怎么处理？             | 期初与差异原则     | 期初导入；出入库流水（对内可配扣减参数，对客不强调） |

### 5.4 分步实施路径

1. 先按场景一跑通报工工资（可压缩并行，但**工资口径先签字**）。
2. 盘点期初，建仓库与物料。
3. 配置领料/入库路径（快速领料、快速入库优先，降低门槛）。
4. **对内**：定库存相关功能参数与仓管角色菜单（含扣减相关权限，不写进对外 PPT）。
5. 试运行：领一笔料、报一笔工、入一笔成品，三笔能对上。
6. 验收：仓管与主任认可「料出、货进」流程；工资链路不被破坏。

### 5.5 话术

- 「报工解决的是**人的钱**；领料和入库解决的是**料和货**。两边一齐，吵架少一半。」
- 「你们不一定要上大库存系统，先做到：**领有单、入有单、能查流水。**」
- 「后面若要按工单发料，升到场景三即可，数据还能接着用。」

### 5.6 MVP / 明确不做

| 做                                        | 不做（对客）                                |
| ----------------------------------------- | ------------------------------------------- |
| 快速报工+工资；领料；成品入库；仓库与流水 | 完整任务派工（场景三）                      |
| 角色里配置库存相关能力（含扣减）          | 对外宣传「库存扣减场景」；完整 WMS/库位波次 |
|                                           | 销售/BOM/计划/采购/质量                     |

## 6. 场景三：任务报工 + 工资核算 + 领料 + 成品入库

### 6.1 适合什么样的企业

- 已有或愿意建立：**工单/工序任务 → 报工** 的纪律。
- 需要「谁在做什么、做了多少」可追溯，而不只是快速记一笔。
- 组织：主任/计划能下发任务；仓管配合按单或按需领料入库。
- 数据：工艺路线稳定，工序名称与工价可匹配。
- 认知：接受「先有任务再报工」比纯快速报工多一步。

### 6.2 场景优势

1. **过程可控**：任务清晰，适合订单交期紧、工序多的机加/装配。
2. **计薪更稳**：报工挂在任务/工序上，工价匹配更准。
3. **物料与任务可对齐**：为后续按单领料、按单入库打基础。
4. **上承场景一/二，下接场景四**：是「车间数字化」的标准形态。

### 6.3 重点调研内容 → 对应系统功能

| 调研问题                     | 要拿到的结论           | 对应系统功能                              |
| ---------------------------- | ---------------------- | ----------------------------------------- |
| 工单谁开、任务怎么派到人？   | 下发规则、执行人       | 生产工单；员工组别；小程序待领/今日待报工 |
| 是否允许无任务快速报工并存？ | 生产模式               | 业务规则「生产模式」                      |
| 领料是否绑工单？             | 工单领料 / 批量 / 快速 | 领料管理（多模式）                        |
| 入库是否绑工单？超收如何？   | 工单入库规则           | 成品入库；入库管理                        |
| （含工资、仓库调研）         | —                      | 同场景一、二                              |

### 6.4 分步实施路径

1. 主数据：产品、工艺路线、工价、仓库、物料。
2. 配置生产模式（标准任务报工为主）。
3. 培训主任：开立工单 → 下发 → 审核报工。
4. 培训工人：领任务 → 报工；仓管：领料/入库。
5. 试点：选 1～2 个常规产品全流程（工单→报工→领料→入库→工资）。
6. 验收：任务闭环 + 工资可核对 + 出入库可追溯。

### 6.5 话术

- 「快速报工适合先跑起来；你们若已经在派工，就用**任务报工**：每笔产量都挂在任务上，交期和工资都更好管。」
- 「领料、入库还是你们熟悉的动作，只是和任务对上号，月底不用三本账对来对去。」

### 6.6 MVP / 明确不做

| 做                                 | 不做（对客）                             |
| ---------------------------------- | ---------------------------------------- |
| 工单任务报工、工资、领料、成品入库 | 销售订单驱动的计划与采购（场景四）       |
| 对内配置扣减等库存参数与权限       | 对外「扣减」卖点；完整质量模块（场景五） |

## 7. 场景四：销售订单 → 采购闭环（含生产与库存）

**对外全称**：销售订单 + BOM 设计 + 计划排产 + 生产管理 + 任务报工 + 工资核算 + 库存管理 + 采购管理。

### 7.1 适合什么样的企业

- 接单后，需要能说清楚：**这单什么时候能交货、现在差哪些料、计划哪天开工、该去采购什么**。
- 组织上：销售/技术（BOM）/计划/生产/仓管/采购有分工（可兼职，但**职责要分清**）。
- 数据：客户、物料、BOM 或可设计、供应商基础可用。
- 认知：关键用户能接受「订单驱动下游单据」，愿意改掉纯口头插单习惯（或约定例外流程）。

**不适合硬上四的**：编码混乱、无人维护 BOM、采购全凭老板记忆且拒绝留痕——应先一/二/三。

### 7.2 场景优势

1. **一张订单牵出下游**：减少「销售答了交期、车间不知道、采购没备料」。
2. **BOM/设计进系统**：变型、非标有落点（设计任务 / EBOM）。
3. **计划与生产衔接**：计划可生成工单、采购申请。
4. **库存与采购闭环**：需求→申请→订单→入库可追溯。
5. **车间能力复用场景三**：报工工资不推倒重来。

### 7.3 重点调研内容 → 对应系统功能

| 调研问题                                     | 要拿到的结论                                          | 对应系统功能                             |
| -------------------------------------------- | ----------------------------------------------------- | ---------------------------------------- |
| 订单如何评审？是否有非标设计？               | 审核流、是否走设计任务                                | 销售订单；设计任务；EBOM；产品 BOM       |
| 计划如何排？是否按订单生成？                 | 计划员职责、例外插单                                  | 生产计划；自动生成单据类功能参数         |
| BOM 里哪些自己做、哪些外买、哪些外协？谁定？ | 外购/外协从哪一步开始提采购（订单后 / 计划后 / 手工） | 生产计划生成采购申请；采购申请、采购订单 |
| 供应商与交期谁维护？                         | 主数据与跟单人                                        | 供应商档案；采购订单；采购明细           |
| 成品如何发运？（若本期要）                   | 是否纳入本期                                          | 发货管理（可标为可选增强）               |
| （含场景三车间与库存调研）                   | —                                                     | 生产工单、报工、工资、出入库等           |

### 7.4 分步实施路径

1. **诊断**：四维评估；主数据差距清单（BOM/客户/供应商）。
2. **车间底座**：若报工工资未上，先并行最小试点（场景一或三），避免四条线同时炸。
3. **主数据月**：编码规则、BOM 模板、工艺、仓库、供应商。
4. **订单→计划→工单** 打通一条标准产品样例。
5. **计划→采购申请→采购订单→入库** 打通缺料样例。
6. **车间**：任务报工 + 领料 + 成品入库 + 工资。
7. **对账与制度**：插单、改 BOM、急单规则书面化。
8. **验收**：从一张销售订单能追到计划、工单、采购、库存与报工工资。

### 7.5 话术

- 「你们缺的不是再多一个报表，而是**接单之后自动问清楚：设计好了没、料齐了没、谁在干、货进仓了没。**」
- 「车间报工我们能先小范围跑；订单和采购是给老板装上『驾驶仪表』，但仪表要有数，前面的主数据得愿意整理。」
- 「一人兼计划兼采购也行，系统按职责开菜单，不是按编制凑人头。」

### 7.6 MVP / 明确不做

| 做                                                                                  | 可选增强                 | 本期不做（除非单列）                |
| ----------------------------------------------------------------------------------- | ------------------------ | ----------------------------------- |
| 销售订单、BOM/设计任务、生产计划、生产工单、任务报工、工资、库存出入、采购申请/订单 | 发货、框架合同、复杂外协 | 完整 QMS/质量追溯大模块（见场景五） |
|                                                                                     |                          | 对外不把「库存扣减」当作独立场景    |

## 8. 场景五：场景四 + 质量管理

**对外全称**：在场景四全部能力上增加质量管理。

### 8.1 适合什么样的企业

- 客户或行业要求：**出厂检验记录、不良/报废可追溯**。
- 质量争议影响回款或品牌。
- 组织：有质检员（可兼职），愿意按模板勾检。
- 已具备或同步建设场景四的主数据与订单生产闭环。

### 8.2 场景优势

1. **质量留痕**：出厂质检、模板、报废有据。
2. **与生产一体**：质检工单/任务可和产线衔接，而不是另起一套表格。
3. **减少客诉扯皮**：检验项、判定、处理方式可回放。
4. **在场景四上叠加**：不推翻订单与生产链路。

### 8.3 重点调研内容 → 对应系统功能

| 调研问题                     | 要拿到的结论       | 对应系统功能                       |
| ---------------------------- | ------------------ | ---------------------------------- |
| 出厂检哪些项？谁检谁放行？   | 模板与角色         | 质检模板；出厂质检；小程序质检任务 |
| 不良如何分类？是否影响计薪？ | 不良品项与扣款规则 | 不良品项；报工不良；计薪口径       |
| 报废如何审批？补料/返工？    | 流程               | 报废品管理；相关字典               |
| 是否要独立质检工单？         | 是/否              | 质检工单                           |
| （含场景四调研）             | —                  | —                                  |

### 8.4 分步实施路径

1. 场景四主链路稳定（至少一条样例订单闭环）。
2. 梳理质检模板（先 1～2 个主力产品）。
3. 配置质检角色与小程序质检入口。
4. 试点：出厂检 + 一次报废流程。
5. 与工资/报工不良规则对齐。
6. 验收：抽一张订单能看到生产与质检记录。

### 8.5 话术

- 「质量模块不是为了『看起来正规』，是为了**出厂有记录、客诉能回放**。」
- 「建议订单和生产跑顺再加质检模板，否则检了也找不到是哪张单、哪个工序的问题。」

### 8.6 MVP / 明确不做

| 做                                     | 不做（除非单列）                             |
| -------------------------------------- | -------------------------------------------- |
| 质检模板、出厂质检、报废、必要质检工单 | 完整质量追溯平台（QMS 大图）、实验室 LIMS 等 |

## 9. 通用配置与角色权限要点

### 9.1 角色映射（一人多岗时合并）

| 岗位（可兼职） | 典型菜单/能力                                    |
| -------------- | ------------------------------------------------ |
| 系统管理员     | 组织人员、角色、功能参数、业务规则、基础档案     |
| 车间主任       | 工单、工序报工审核、报工确认、工时/工资查看      |
| 工人           | 小程序：报工、工时工资、领料/入库（若授权）      |
| 仓管           | 领料发料、出入库、仓库；**对内**可含扣减记录确认 |
| 计划           | 生产计划、设计任务协同                           |
| 采购           | 采购申请/订单、供应商                            |
| 销售           | 销售订单、客户、发货（若开）                     |
| 质检           | 质检模板、出厂质检、报废、质检任务               |
| 财务/老板      | 工资核算查询、关键报表（按需）                   |

### 9.2 功能参数（实施必查）

| 参数                  | 场景           | 说明                                       |
| --------------------- | -------------- | ------------------------------------------ |
| 工资推送模式          | 一～五         | 报工即推送 / 审核后 / 手动                 |
| 生产模式              | 三～五         | 标准任务 vs 精简等                         |
| 库存扣减方式等        | 二～五（对内） | **只写进配置清单与权限，不写进对外场景名** |
| 单据自动审核/自动生成 | 二～五         | 按企业习惯收紧或放开                       |

### 9.3 库存扣减（仅实施备忘）

- 对客材料、场景名称、一页纸话术中 **不出现**「库存扣减」作为卖点。
- 实施检查清单中勾选：功能参数已选、仓管/管理员角色已授权相关菜单、试点单据已走通确认。
- 若客户主动问「账怎么扣的」，用业务语言回答：「按你们选的领料/报工口径，系统自动预扣并确认，保证库存账和现场一致。」

## 10. 售前话术总表

| 场景 | 30 秒电梯话术                                                    |
| ---- | ---------------------------------------------------------------- |
| 一   | 工人手机报工，主任一审，计件工资自动汇总——先把「人的钱」算清楚。 |
| 二   | 在算清工资的同时，领料、成品入库留单，料和货也对得上。           |
| 三   | 有工单有任务再报工，产量、物料、工资三条线挂在任务上。           |
| 四   | 从销售订单到 BOM、计划、生产、库存、采购一条链，接单就能往下拆。 |
| 五   | 在四的基础上加出厂质检和报废，交期与质量都能留痕。               |

**扩场景过渡句**：

- 「数据还没理顺、人还怕系统，我们**先上场景一**，见效了再加料和货。」
- 「你们已经有仓管诉求，但派工还很随意，**场景二**最合适。」
- 「派工已经正规，就上**场景三**；等订单和采购也要进系统，再谈四。」
- 「组织和主数据都到了，直接谈四；有出厂检硬要求，四后面紧跟五。」
