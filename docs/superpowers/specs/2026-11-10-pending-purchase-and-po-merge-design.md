# 待采购清单 + 采购订单合并（双轨）

**日期：** 2026-11-10  
**仓库：** i-doms-web  
**状态：** 已确认双轨都做；前端一期已落地（清单页 / 订单合并 / 功能参数）  
**迭代：** 机泵1.6.3

---

## 1. 目标

现场两类痛点并存，分轨解决、禁止塞进同一个池：

| 轨  | 名称             | 解决什么                           | 池子里是什么                   |
| --- | ---------------- | ---------------------------------- | ------------------------------ |
| A   | **待采购清单**   | 申请零散、攒一波再买               | 采购申请**未转完**的可采剩余量 |
| B   | **采购订单合并** | 已生成多张零散订单，再按供应商捏单 | 已存在、**未执行**的采购订单   |

交互均对齐「待出库列表」：筛选 + 勾选 + 批量处理 + 侧栏角标。

---

## 2. 决策摘要

| 项                   | 选择                                                                                                                        |
| -------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| 待采购数据源         | 申请行 `poGenStatus ≠ 已生成采购` 的计划采购量（后续可扩展部分转剩余量）                                                    |
| 待采购合并结果       | 按供应商生成/并入**待审核**采购订单（复用现有生成采购订单能力）                                                             |
| 明细合并键（申请侧） | 物料编码 + 供应商 + 销售单号（与现 `purchaseMerge.mergeKey` 一致）；规格/单价不一致时仍按键合并数量（现网口径），一期不另拆 |
| 订单合并可合状态     | **待提交、待审核、已拒绝**                                                                                                  |
| 订单合并禁止         | 进行中 / 部分收货 / 已完成 / 已作废 / 已终结                                                                                |
| 订单合并结果         | 同供应商多单 → 一张主单（保留最早单或新建，一期：**保留勾选中创建最早的一张为主单**，其余作废并迁明细）；明细一致则数量相加 |
| 订单明细一致键       | 物料编码 + 规格型号 + 材质 + 采购单位 + 含税单价 + 税率 + 收货仓                                                            |
| 交期不同             | 取最早交货日写入合并行；来源单号写入备注/来源字段                                                                           |
| 功能参数             | ① 启用待采购清单 ② 待采购合并：手动 / 自动 ③ 启用订单合并 ④ 订单合并：手动 / 自动；自动一期可只留开关，定时调度二期         |
| 命名                 | 菜单「待采购清单」；订单侧工具栏「按供应商合并」                                                                            |

## 3. 信息架构

```
采购管理
├── 采购申请
├── 待采购清单          /procurement/pending-purchase   【新】
├── 采购订单            （工具栏增加「按供应商合并」）
├── 采购收货
├── …
```

侧栏角标：

- 待采购清单：未转采购申请行数（或可合并供应商组数，一期用**未转行数**）
- 采购订单：保持现有「待审核」单数角标；合并不另开角标

---

## 4. 轨 A · 待采购清单

### 4.1 列表

- 形态：可对标待出库——筛选、勾选、主从或分组表
- 默认按**供应商**分组展示未转明细
- 列建议：供应商、申请单号、物料编码/名称、规格、计划采购量、单位、销售单号、交期、紧急度、来源

### 4.2 操作

- **按供应商合并生成采购订单**：勾选行/组 → 进入现有「生成采购订单」页（带入对应申请）或页内确认生成
- 无供应商行：标红，须先补供应商再合并
- 生成成功后申请行 `poGenStatus = 已生成采购`，行从本清单消失

### 4.3 与现网关系

- 采购申请页「批量转采购订单」保留
- 待采购清单是**工作台视角**（按供应商攒单），底层仍走 `mergeRequisitionLines` + 生成 PO

---

## 5. 轨 B · 采购订单合并

### 5.1 入口

- 采购订单列表工具栏：**按供应商合并**（须先勾选 ≥2 张且同供应商、状态合法）
- 可选：仅「待审核」快捷筛选下高亮该按钮

### 5.2 预览与确认

弹窗/页展示：

- 将被保留的主单号
- 将被作废的单号列表
- 合并后明细（标注数量相加 vs 分行）
- 确认后写回主单、作废从单、操作日志

### 5.3 回写与追溯

- 主单明细保留/合并 `sourceReqNos`、原订单号
- 从单状态 → 已作废；备注「已合并至 {主单号}」
- 若从单曾占申请量：申请仍视为已生成（不回池）；仅单据层合并

## 6. 功能参数（基础配置）

| 参数键（建议）               | 含义               | 默认   |
| ---------------------------- | ------------------ | ------ |

---

## 7. 验收要点

**待采购**

- [ ] 仅未转申请行出现；全部转完后消失
- [ ] 按供应商勾选可生成采购订单，明细一致数量合并
- [ ] 侧栏角标随未转行数变化

**订单合并**

- [ ] 不同供应商不可合；进行中不可合
- [ ] 同物料同价同仓数量相加；不一致分行
- [ ] 从单作废可追溯至主单
