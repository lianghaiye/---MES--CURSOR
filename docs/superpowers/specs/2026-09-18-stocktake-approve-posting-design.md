# 盘点审核与过账设计

**日期：** 2026-09-18  
**仓库：** i-doms-web  
**状态：** 已确认

## 1. 目标

盘点单改为审核流；审核通过后按配置自动或手动生成盘盈入库 / 盘亏出库；支持过账失败标记与手工重试；详情「关联单据」展示联动出入库。

## 2. 已确认决策

| 项           | 选择                                                           |
| ------------ | -------------------------------------------------------------- |
| 选料         | 抽盘为主 +「加载本仓库存」                                     |
| 加载默认     | **自由 + 按单分行**（账面可对齐仓内总量）                      |
| 盘盈         | 一律进 **自由备货**                                            |
| 盘亏         | 优先自由可用（自由−软锁）；不足则拦截，支持强制（含软锁/按单） |
| 盘点类型     | 期初调整 / 期末调整 / 成本调整 / 其他调整                      |
| 清单标题     | 「盘点清单」                                                   |
| 单据状态     | 待审核 → 审核通过 / 已拒绝；过账成功 → **已过账**              |
| 过账触发     | **可配置**：审核通过后自动生成 / 手动点「生成盘盈盘亏」        |
| 自动过账失败 | **仍审核通过**，标记过账失败，支持手工再次发起                 |

## 3. 状态机

```
待审核 ──审核通过──► 审核通过 ──过账成功──► 已过账
   │                    │
   └──已拒绝            └──过账失败（仍为「审核通过」，postingStatus=failed）
```

| 状态     | 可编辑 | 可审核/拒绝 | 可生成盘盈盘亏           |
| -------- | ------ | ----------- | ------------------------ |
| 待审核   | 是     | 是          | 否                       |
| 审核通过 | 否     | 否          | 是（手动模式或失败重试） |
| 已拒绝   | 否     | 否          | 否                       |
| 已过账   | 否     | 否          | 否                       |

字段补充：

- `stocktakeType`：盘点类型
- `postingStatus`：`pending` \| `success` \| `failed`（仅审核通过后有意义）
- `postingError`：最近一次过账失败原因
- `autoPostOnApprove`：下单时可快照当时全局配置（可选，演示期读全局即可）

## 4. 全局配置

与调拨「入库方签收」类似，盘点管理工具栏开关：

- **审核通过后过账**：`自动` / `手动`
- 存储：`i_doms_stocktake_settings`，`autoPostOnApprove` 默认 `true`

## 5. 选料与账面

- 「从库存添加」：弹窗可选全部/自由/按单（对齐调拨选库存交互，可简化）
- 「加载本仓库存」：当前仓全部在库批，**自由与按单分行**；账面=该行数量
- 实盘默认=账面，可改；差异=实盘−账面

## 6. 过账规则（生成盘盈盘亏）

对每条有差异明细：

1. **盘盈（diff>0）**：生成盘点入库，入自由备货（不写 salesOrder\*）
2. **盘亏（diff<0）**：
   - 若行归属为自由：需求量 ≤ 可用自由 → 盘点出库；否则 fail（除非 force）
   - 若行归属为按单：默认允许按该批数量盘亏（已按行隔离）；若另有软锁再校验
3. 整单：任一行非强制失败 → 整单过账失败，已生成的单据需回滚或标记（演示期：先校验全部再生成）
4. 成功：写 `linkedOutbound*` / `linkedInbound*`，状态 **已过账**，`postingStatus=success`

## 7. 审核通过行为

1. 状态 → 审核通过，`postingStatus=pending`
2. 若配置为自动：立即调用过账
   - 成功 → 已过账
   - 失败 → 保持审核通过，`postingStatus=failed`，写入 `postingError`，可点「重新过账」
3. 若配置为手动：停留审核通过，用户点「生成盘盈盘亏」

## 8. 详情关联单据

Tab：**基本信息 | 盘点清单 | 关联单据**

关联单据列出本单生成的盘点入库、盘点出库（单号可跳转）。

## 9. 一期不做
