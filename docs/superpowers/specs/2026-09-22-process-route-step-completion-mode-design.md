# 工艺路线步骤「完成方式」与下发勾选

**日期：** 2026-09-22  
**仓库：** i-doms-web  
**状态：** 已确认并落地（前端一期）  
**范围：** 工艺路线主数据（列/步配置）+ 生产工单下发任务生成（极简非时序优先）

## 1. 背景与目标

同一工艺路线「第 N 步」可配置多道并行工序（同 `stepNo`、不同 `rowNo`）。业务上存在两种完成语义：

1. **本步所有工序都要做** → 下发时全部生成任务。
2. **本步只需做其中一部分** → 路线上预置候选工序，**下发时由计划员勾选**本次实际下发的工序。

目标：在路线配置与下发交互上把这两种语义说清、可配置、可落地；与现网极简非时序（任务池领取、无步间门控）兼容。

## 2. 命名（已确认）

| 层级       | 文案         | 说明                                       |
| ---------- | ------------ | ------------------------------------------ |
| 字段名     | **完成方式** | 挂在「第 N 步 / 这一列」上，不是单道工序上 |
| 选项 `all` | **全部完成** | 本步所有已配工序都要做完                   |
| 选项 `any` | **选做完成** | 本步从候选中选本次要做的工序下发           |

副文案（表头/帮助）：

- 全部完成：本步所有工序都要做完
- 选做完成：下发时从本步候选工序中勾选，勾中的都要做完

不使用「并行 AND/OR」「全选/多选」等易与「并行工序」结构混淆的说法。

## 3. 配置规则（工艺路线）

### 3.1 放置位置

- 配置在网格**列头（第 N 步）**，与该步下所有 `rowNo` 工序共用。
- 该步仅 1 道工序时：默认 **全部完成**，完成方式可灰显或隐藏（语义无差别）。

### 3.2 默认与校验

- 新建步 / 未配置：默认 `all`（全部完成）。
- 该步有效工序数 = 0：不校验完成方式。
- 该步有效工序数 ≥ 2 且为选做完成：允许保存（候选集合 = 该列全部已配工序）。

### 3.3 数据模型（建议）

在路线持久化中增加**按步**策略（与 `steps[]` 扁平列表并存时，以 `stepNo` 对齐）：

```text
stepPolicies: [
  { stepNo: 1, completionMode: 'all' },
  { stepNo: 2, completionMode: 'any' },
  ...
]
```

- `completionMode`: `'all' | 'any'`
- 一期不做 `n_of_m` / 报工后自动作废同组任务。

扁平 `steps` 生成工单工序时：每条工序可冗余带上所属步的 `completionMode`，便于下发页按步分组，无需再查路线。

工单快照建议同时保留 `stepPolicies`（或等价结构），避免事后改路线影响已下发/在制单的解释。

## 4. 下发行为（已确认）

前提：当前为**极简非时序**——不做「本步未完成则锁下一步」；本设计只约束**哪些工序生成任务**。

| 完成方式     | 下发                                                                     |
| ------------ | ------------------------------------------------------------------------ |
| **全部完成** | 该步所有已配工序**全部生成任务**；下发页不提供少发勾选                   |
| **选做完成** | 下发页展示该步候选工序列表，**计划员勾选本次下发集合**；仅勾中项生成任务 |

### 4.1 选做完成 · 勾选约束

1. **至少勾选 1 道**，否则拦截下发并提示。
2. **勾中的工序全部要做完**（下发子集 + 对勾中集合按「都要做」理解）。
3. 未勾中的候选：**不生成任务**（本期不做「下发后报工收口/自动作废」）。
4. 默认勾选策略（实现可选其一，需在 UI 标明）：
   - 推荐默认：**全部候选预勾**，计划员去掉不需要的；或
   - **全部不预勾**，强制显式选择。
   - 产品一期建议：**全部候选预勾**，减少漏勾。

### 4.2 多步混合

一张工单可同时存在「全部完成」步与「选做完成」步：

- 仅对 `completionMode === 'any'` 且该步工序数 ≥ 2 的步弹出/展示勾选区。
- `all` 步静默全发，勾选区可不展示或只读展示「将下发全部」。

### 4.3 与任务生成的衔接

- 入参：工单工序快照 + 下发勾选结果（按 `stepNo` → 选中的 `processId` / 工序行 id 列表）。
- `buildWorkOrderProcessesFromGrid` / `dispatchWorkOrderToMobile` 路径：生成任务前按勾选过滤；`all` 步不过滤。
- 任务上保留 `stepNo`、`completionMode`，便于监管看板与后续扩展。

## 5. UI 要点

### 5.1 工艺路线编辑

- 列头「第 N 步」旁或下方：下拉/单选 **完成方式**（全部完成 / 选做完成）。
- 选做完成时可用轻量提示：「下发时将从本步工序中勾选」。

### 5.2 工单下发

- 若存在任一「选做完成」且候选 ≥ 2：下发确认区增加 **「选做工序勾选」** 分组（按步）。
- 每组：步序号 + 工序多选（名称/编号）。
- 校验失败文案示例：「第 3 步为选做完成，请至少选择一道工序」。

## 6. 非目标（本期不做）

- 步间时序门控（完成方式满足前锁定下一步）。
- 下发多候选后「报工完成其一即自动终止其余」。
- `n_of_m`（完成不少于 K 个）。
- 计薪特殊规则（仍按实际生成并报工的任务计）。
- 改最大步数 / 并行上限。

## 7. 验收

1. 路线列头可配置完成方式；默认全部完成；单工序步行为正确。
2. 全部完成步：下发生成该步全部任务。
3. 选做完成步：下发必须勾选 ≥1；仅勾中项有任务；未勾中无任务。
4. 混合步工单下发：仅选做步出现勾选，全部完成步不受影响。
5. 已下发工单的工序集合不因事后改路线完成方式而回写改变（依赖工单快照）。
