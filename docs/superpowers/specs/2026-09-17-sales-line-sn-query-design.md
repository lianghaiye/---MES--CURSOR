# 销售明细 · 按工业 SN 查销售单设计

**日期：** 2026-09-17  
**仓库：** i-doms-web  
**状态：** 待评审

## 1. 背景与目标

产品回厂售后时，现场常只有铭牌上的工业 SN。用户希望在 **销售明细** 列表用 SN 反查对应销售订单（及客户、产品行），无需先知道销售单号。

现状：

- 销售明细是 **销售行** 粒度（`SalesOrderLineListView` / `flattenSalesOrderLines`），一行对应订单明细，不是「一台实物」。
- 工业 SN 存在 `industrialLabelStore`，通过 `salesOrderId` / `salesLineId` / `labelCode` 挂到销售行；一行数量为 N 时可有最多 N 个 SN。
- 销售订单详情已有「工业标识」页签与 SN 明细；销售明细列表 **无 SN 筛选与列**。
- 装牌策略（方案 A）：完工入库不强制挂 SN，装牌确认时再绑定实物；因此「SN ↔ 具体一台」未必在列表层建实体，但 **SN ↔ 销售行** 在申请成功后即存在，足够支撑售后查单。

**目标：** 在销售明细保持销售行粒度的前提下，支持按 SN 检索并落到销售行，行上展示 SN 数量摘要，点开抽屉查看该行全部 SN 并跳转销售订单。

## 2. 已确认决策

| 项         | 选择                                                |
| ---------- | --------------------------------------------------- |
| 列表粒度   | 保持销售行一行；不按 SN 拆行                        |
| 检索能力   | 精确 + 模糊双模式（默认精确；可勾选模糊）           |
| 行上展示   | 数量摘要（已申请 n / 已刻录 a/n），点击打开 SN 抽屉 |
| 看全部 SN  | 本页抽屉（方案 A），命中高亮；提供打开销售订单      |
| 独立菜单   | 不做「售后 SN 查询」新菜单                          |
| 主数据模型 | 不改工业标识主模型；只读聚合 + 筛选                 |

## 3. 筛选与命中（§1）

### 3.1 筛选项

销售明细筛选区新增：

- **SN 码**：输入框，占位「完整 SN 或片段」
- **模糊匹配**：Checkbox，默认不勾 = 精确匹配

### 3.2 命中规则

| 模式         | 规则                                                                                                          |
| ------------ | ------------------------------------------------------------------------------------------------------------- |
| 精确（默认） | `labelCode` 全等（trim，大小写不敏感）                                                                        |
| 模糊         | `labelCode` 包含输入片段（去空白，大小写不敏感）；输入有效长度 **&lt; 4** 时不执行查询，提示「至少输入 4 位」 |

### 3.3 命中结果

- 先在工业标识 labels 中命中 → 收集 `salesLineId` → 过滤销售明细行。
- 列表仍一行一销售明细；同一行多个 SN 命中只出现一次。
- 无命中：空表 + 文案「未找到匹配 SN」。
- **作废** SN（`LABEL_STATUS.VOID`）不参与检索。
- 无 `salesLineId` 的历史 SN 查不到（本期不清洗；二期可在标识管理补挂）。

## 4. 列表列与 SN 抽屉（§2）

### 4.1 列「工业 SN」

建议位置：产品编码之后；纳入列设置，默认可显示。

| 行状态             | 展示                                               |
| ------------------ | -------------------------------------------------- |
| 无有效 SN          | `—`                                                |
| 有申请、未装牌     | 链接：`已申请 n`                                   |
| 有装牌             | 链接：`已刻录 a/n`（a = 已装牌数，n = 有效 SN 数） |
| 本次筛 SN 命中本行 | 文案旁 Tag：`命中`                                 |

点击链接 → 打开本行 SN 抽屉（不离开列表）。

### 4.2 SN 抽屉

- 标题：`SN 明细 · {产品名称}`
- 副标题：销售单号、客户名称
- 表列：SN 码、标识状态、刻录/装牌状态、申请单号、注册时间
- 若本次筛 SN 命中：命中行 **高亮并置顶**
- 操作：SN 可跳转标识管理（带 `labelCode` query）；底部「打开销售订单」进入订单详情并定位「工业标识」页签
- 空态：本行暂无工业标识 SN

## 5. 数据与实现要点（§3）

### 5.1 关联

```
销售明细行.id  ←→  industrialLabel.salesLineId
筛 SN：labels(labelCode 命中) → salesLineId 集合 → filter 销售明细行
摘要：按 salesLineId 聚合有效 labels → n、a（nameplateMountedAt / engrave 已刻录）
```

复用现有能力：`industrialLabelState.labels`、`getLabelByCode`、按 `salesLineId` 过滤；销售明细侧在 `filterSalesOrderLines` / 行 enrich 中接入。

### 5.2 导出

销售明细导出可选增加字段「工业 SN 摘要」（`已申请 n` / `已刻录 a/n` / 空），**不**展开全部 SN 码。

### 5.3 一期范围

- 仅改销售明细列表：筛选项 +「工业 SN」列 + SN 抽屉
- 只读；不做装牌 / 作废 / 补申请

### 5.4 非目标

- 不把销售明细拆成 SN 行台账
- 不新建售后 SN 查询菜单
- 不在本页维护工业标识生命周期
- 不解决未挂销售行的脏数据清洗

## 6. 交互流程（售后）

1. 打开销售明细 → 输入铭牌 SN（默认可精确；片段则勾选模糊）→ 搜索
2. 列表留下对应销售行，列上见摘要 +「命中」
3. 点「已申请/已刻录」打开抽屉，确认 SN，点「打开销售订单」进入详情

## 7. 验收要点

- [ ] 精确输入完整有效 SN，仅命中对应销售行，且带「命中」Tag
- [ ] 模糊不足 4 位有提示且不查；≥4 位可命中多行
- [ ] 作废 SN 不可命中
- [ ] 无 SN 行显示 `—`；有 SN 行摘要正确（n、a/n）
- [ ] 抽屉列表完整，命中行置顶高亮；可跳标识管理与销售订单工业标识页签
- [ ] 导出含摘要字段（若启用）且不展开全部 SN

## 8. 后续可选

- 销售订单列表同样支持 SN 精查跳转
- 移动端/售后专用「扫 SN 查单」入口
