# 销售明细 · 按工业 SN 查销售单设计

**日期：** 2026-09-17  
**仓库：** i-doms-web（PC）+ i-doms-mobile（小程序）  
**状态：** 已确认（移动端为微信小程序，非 Web H5）

## 1. 背景与目标

产品回厂售后时，现场常只有铭牌上的工业 SN。用户希望：

1. 在 **销售明细** 列表用 SN 反查对应销售订单（及客户、产品行）；
2. 在 **IDOMS 微信小程序** 扫码/输入 SN 直接看到销售单摘要。

现状：

- 销售明细是 **销售行** 粒度（`SalesOrderLineListView` / `flattenSalesOrderLines`），一行对应订单明细，不是「一台实物」。
- 工业 SN 存在 `industrialLabelStore`，通过 `salesOrderId` / `salesLineId` / `labelCode` 挂到销售行；展平行主键为 `` `${order.id}__${line.id}` ``，匹配 SN 时须用行上的 **`lineId`**（= `line.id`）。
- 销售订单详情已有「工业标识」页签与 SN 明细；销售明细列表已支持 SN 筛选与摘要列。
- 装牌策略（方案 A）：完工入库不强制挂 SN；**SN ↔ 销售行** 在申请成功后即存在，足够支撑售后查单。
- 小程序仓 `i-doms-mobile`（uni-app）已有「铭牌任务」；查单为独立售后入口。

**目标：** PC 销售明细保持销售行粒度支持 SN 检索与摘要抽屉；**扫码查单在 IDOMS 微信小程序（`i-doms-mobile`）交付**，不使用 Web H5。

## 2. 已确认决策

| 项         | 选择                                                                  |
| ---------- | --------------------------------------------------------------------- |
| 列表粒度   | 保持销售行一行；不按 SN 拆行                                          |
| PC 检索    | 精确 + 模糊双模式（默认精确；可勾选模糊）                             |
| 行上展示   | 数量摘要（已申请 n / 已刻录 a/n），点击打开 SN 抽屉                   |
| 看全部 SN  | 本页抽屉，命中高亮；提供打开销售订单                                  |
| 移动端     | **i-doms-mobile 小程序**「扫码查单」（`uni.scanCode` + 手输，仅精确） |
| 独立菜单   | PC 不做售后 SN 侧栏；小程序工作台增加「扫码查单」                     |
| 主数据模型 | 不改工业标识主模型；只读聚合 + 筛选                                   |

## 3. 筛选与命中（PC §1）

### 3.1 筛选项

销售明细筛选区新增：

- **SN 码**：输入框，占位「完整 SN 或片段」
- **模糊匹配**：Checkbox，默认不勾 = 精确匹配

### 3.2 命中规则

| 模式         | 规则                                                                                                |
| ------------ | --------------------------------------------------------------------------------------------------- |
| 精确（默认） | `labelCode` 全等（trim，大小写不敏感）                                                              |
| 模糊         | `labelCode` 包含输入片段（去空白，大小写不敏感）；有效长度 **&lt; 4** 时不查，提示「至少输入 4 位」 |

### 3.3 命中结果

- 先在工业标识 labels 中命中 → 收集 `salesLineId` → 过滤销售明细行（`row.lineId`）。
- 列表仍一行一销售明细；同一行多个 SN 命中只出现一次。
- 无命中：空表 +「未找到匹配 SN」。
- **作废** SN 不参与检索。
- 无 `salesLineId` 的 SN 查不到（本期不清洗）。

## 4. 列表列与 SN 抽屉（PC §2）

### 4.1 列「工业 SN」

建议位置：产品编码之后；纳入列设置，默认显示。

| 行状态             | 展示               |
| ------------------ | ------------------ |
| 无有效 SN          | `—`                |
| 有申请、未装牌     | 链接：`已申请 n`   |
| 有装牌             | 链接：`已刻录 a/n` |
| 本次筛 SN 命中本行 | 文案旁 Tag：`命中` |

### 4.2 SN 抽屉

- 标题：`SN 明细 · {产品名称}`；副标题：销售单号、客户
- 表列：SN 码、标识状态、刻录/装牌状态、申请单号、注册时间
- 筛 SN 命中：命中行高亮并置顶
- 操作：跳转标识管理；「打开销售订单」进详情「工业标识」页签

## 5. 小程序「扫码查单」（§4，仓：`i-doms-mobile`）

### 5.1 入口

- 工作台模块：**扫码查单** → `/pages/sn-lookup/index`
- 导航栏标题：扫码查单
- 支持 `?sn=` 预填并自动精确查询

### 5.2 交互

1. **扫码**：`uni.scanCode`（条码/二维码）；取消不提示；失败提示「扫码失败，请改用手输」
2. **手输**：完整 SN → 查询（**仅精确**）
3. **命中结果卡**：SN、标识/装牌状态、销售单号、客户、产品名称/编码、规格、材质、申请单号、注册时间；可进「标识详情」
4. **未命中 / 作废**：明确文案
5. **再扫一单**：清空结果

### 5.3 查询

- 工具：`lookupSalesOrderBySn`（`industrialLabelBridge.js`）
- 与 PC 同源 storage key `i_doms_industrial_labels_v1`；排除作废；须有 `salesLineId`

## 6. 数据与实现要点

### 6.1 公共查询

新建工具（建议 `src/utils/salesSnLookup.js`）：

- `normalizeSnCode(input)`
- `matchLabelsBySn(labelCode, { fuzzy })` → 有效且未作废的 labels
- `summarizeLineLabels(salesLineId)` → `{ total, mounted, summaryText }`
- `lookupSalesBySn(labelCode, { fuzzy })` → `{ ok, message, labels, salesLineIds }` 或单条结果卡 DTO
- `enrichSalesLineSnSummary(row, labelsByLineId)` → 行字段 `snTotal` / `snMounted` / `snSummaryText`

### 6.2 导出

销售明细导出增加「工业 SN 摘要」字段。

### 6.3 一期范围

- PC：筛选项 +「工业 SN」列 + SN 抽屉（`i-doms-web`）
- 小程序：工作台「扫码查单」+ `uni.scanCode` / 手输精确查单（`i-doms-mobile`）
- **不做** Web H5 `/m/sn-lookup`
- 只读；不做装牌流程混在查单页（装牌仍走「铭牌任务」）

### 6.4 非目标

- 不按 SN 拆销售明细行
- 不做 PC 侧栏「售后 SN 查询」菜单
- 移动端不做模糊多结果列表
- 不清洗无 `salesLineId` 的历史 SN

## 7. 交互流程

**PC：** 销售明细 → 输 SN（精确/模糊）→ 命中行 + 摘要 → 抽屉确认 → 打开销售订单

**移动：** 小程序工作台 → 扫码查单 → 扫或输完整 SN → 结果卡 →（可选）标识详情 → 再扫一单
