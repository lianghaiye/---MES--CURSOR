# 销售明细 · 发货信息列与列顺序调整

**日期：** 2026-09-18  
**仓库：** i-doms-web  
**状态：** 待用户审阅 spec

## 1. 背景与目标

销售明细列表需要补充发货相关信息，并微调列顺序。发货单字段较多，且一行销售明细可能对应多张发货单，不宜在列表平铺多列。

**目标：**

1. 在「交付方式」后增加 **发货信息** 列，交互对齐「工业 SN」：摘要可点 → 抽屉展示本行关联发货单；
2. **合同编号** 移到「销售数量」之后；
3. 在「业务员」后增加 **区域**（取销售订单头 `region`）。

## 2. 已确认决策

| 项           | 选择                                                                        |
| ------------ | --------------------------------------------------------------------------- |
| 多发货单展示 | 不拆行；一列摘要 + 抽屉列表                                                 |
| 摘要文案     | `已发货 n`（n = 本行关联发货单张数）；n=0 显示 `—` 且不可点                 |
| 交货方式来源 | 发货单 `shipmentMethod`（非销售单头 `deliveryMethod`，非行 `deliveryMode`） |
| 列表平铺     | 不做发货单号/物流/司机等独立列                                              |
| 导出         | 增加「发货信息」摘要列（与 SN 一致，仅摘要；抽屉明细字段本期不导出）        |
| 筛选         | 本期不新增发货信息筛选项                                                    |

## 3. 列顺序（相关片段）

```
… → 销售数量 → 合同编号 → 已发数量 → 未发数量 → 行发货状态 → 交付方式 → 发货信息 → 库存履约 → …
… → 业务员 → 区域 → 创建时间 → 创建人
```

说明：合同编号从原「业务员」后位置移除，避免重复。

## 4. 发货信息列

### 4.1 关联口径

对本销售明细行 `lineId`（= `line.id`），收集满足以下任一条件的发货单（去重按发货单 `id`）：

- `lineItems` 中存在 `id === lineId` 或 `salesLineId === lineId` 的行；
- `scatterShipments` 中存在同上匹配的散件发货块。

数据源优先：`order.deliveryApplications`（与 `salesLineShipped` 一致）；亦可经 `deliveryOrderStore` 按 `salesOrderId` 对齐，但匹配规则须与上行一致。

排序：按发货日期/创建时间倒序（新在前），便于抽屉浏览。

### 4.2 列表单元格

| 条件           | 展示                   |
| -------------- | ---------------------- |
| 关联张数 n = 0 | `—`（纯文本，不可点）  |
| n ≥ 1          | 可点击链接：`已发货 n` |

点击打开本页抽屉（不跳页）。

### 4.3 抽屉

- 标题：发货信息（或「发货信息 · {产品名}」）
- 副标题：销售单号 · 客户（对齐 `SalesLineSnDrawer`）
- 表格列：

| 列名         | 字段                                       |
| ------------ | ------------------------------------------ |
| 发货单号     | `deliveryCode`（可点，打开发货单详情页签） |
| 交货方式     | `shipmentMethod`                           |
| 物流单号     | `logisticsNo`                              |
| 交货地址     | `deliveryAddress`                          |
| 出库仓库     | `outboundWarehouse`                        |
| 司机姓名     | `driverName`                               |
| 司机联系方式 | `driverPhone`                              |
| 车牌号       | `plateNo`                                  |

- 空表文案：本行暂无发货单
- 页脚：关闭；可选「打开销售订单」（对齐 SN 抽屉）

## 5. 区域字段

- 展平：`flattenSalesOrderLines` 增加 `region: order.region || ''`
- 列表列：业务员后，`key: 'region'`，宽度约 90
- 导出：`salesOrderLineExport` 同步增加「区域」

## 7. 非目标

- 不改发货单主数据模型；
- 不在销售明细增加发货筛选项；
- 不在列表平铺司机/物流等字段；
- 不改造小程序。

## 8. 验收

1. 无发货单的行：发货信息为 `—`，点击无抽屉。
2. 有 1/多张发货单的行：显示 `已发货 1` / `已发货 n`，点击抽屉列出全部关联单及约定字段；交货方式来自发货单。
3. 合同编号列紧跟销售数量；业务员后可见区域。
4. 列设置重置后顺序符合 §3；导出含发货信息摘要与区域，合同编号位置与列表一致。
