# 采购/外协订单「入库状态」统一状态机需求

| 项目        | 内容                                                                                           |
| ----------- | ---------------------------------------------------------------------------------------------- |
| 迭代 / 版本 | 机泵（采购管理 / 外协）增量                                                                    |
| 范围        | 采购订单、采购收货、来料质检（读收货入库态）、外协订单、外协收货、外协回货检                   |
| 类型        | 状态机改造 + 列表一眼可读                                                                      |
| 关联痛点    | 收货已占满数量后，采购订单仍显示「待入库」，列表无法区分「未收货 / 已收货未入库 / 入库进行中」 |

---

## 一、背景与目标

### 1.1 现状问题

- 采购订单「入库状态」仅按 **已确认入库数量 vs 采购数量** 计算，枚举为：`待入库 / 部分入库 / 已入库`。
- 明细层已用「收货占用 + 入库申请占用」管控可操作数量，但 **单据头状态未同步**。
- 典型误导：采购订单全部收货后，列表仍为「待入库」，且无法再从采购订单直接生成入库，用户无法从列表一眼判断卡在收货还是入库。

### 1.2 目标

1. **采购订单 / 外协订单列表仍只用一列「入库状态」**（订单不一定走收货，不宜单独占「收货状态」列）。
2. 状态覆盖：未收货 → 部分/全部收货 → 入库进行中 → 部分/全部入库完成；以及 **全量退货闭环**。
3. **入库类状态优先级高于收货类状态**；**已退货** 与 **已入库** 互斥（全退不得叫已入库）。
4. 收货单（及质检列表所读收货入库态）与订单头状态联动回写。
5. **外协订单采用同一套逻辑**（收货=回货收货，其余同构）。

---

## 二、状态枚举（讲清楚）

### 2.1 采购订单 / 外协订单「入库状态」（单列合成）

| 状态值       | 含义（业务一句话）                                                                     | 典型场景                                                                   |
| ------------ | -------------------------------------------------------------------------------------- | -------------------------------------------------------------------------- |
| **待入库**   | 尚未发生有效收货，也尚未生成/占用入库                                                  | 进行中订单，未收货、未直连生成入库单                                       |
| **部分收货** | 已有收货，但收货数量 **未覆盖** 全部采购（或外协）明细数量；且当前不命中更高优先级状态 | 只收了一部分；或多明细仅部分行有收货                                       |
| **已收货**   | 收货数量已覆盖全部订单行数量；且当前不命中更高优先级状态                               | 收货已收满，尚未生成入库单 / 无已确认入库 / 未全量退货关闭                 |
| **入库中**   | 存在 **未完成确认** 的入库单（见 2.3）                                                 | 已从订单/收货/质检生成入库单，仓库尚未全部确认                             |
| **部分入库** | 无未完成确认入库单；已确认入库数量 &gt; 0；整单 **未** 达到「已入库 / 已退货」闭环     | 部分数量已确认入库，其余仍待入或待处置                                     |
| **已入库**   | 无未完成确认入库单；整单已闭环，且 **存在已确认入库数量**（A &gt; 0）                  | 应入部分已全部确认入库；若另有退货关闭量，属「有入有退」的完成，仍叫已入库 |
| **已退货**   | 无未完成确认入库单；整单已闭环，且 **已确认入库数量为 0**（全靠退货等关闭，从未入库）  | 收货后质检 **全退**、零入库；或等价的整单退货关闭且无入库                  |

> 列表筛选、标签色建议：  
> 待入库=默认；部分收货/已收货=提醒色；入库中=处理中；部分入库=警告；已入库=成功；**已退货=错误/品红类**（与已入库区分）。

### 2.2 采购收货单 / 外协收货单「入库状态」

| 状态值       | 含义                                                                    |
| ------------ | ----------------------------------------------------------------------- |
| **待入库**   | 本收货单尚未生成有效入库单，且未因质检等全量退货关闭                    |
| **入库中**   | 本收货单已关联入库单，且存在未完成确认的入库单                          |
| **部分入库** | 无未完成确认入库单；本收货仅部分数量已确认入库                          |
| **已入库**   | 无未完成确认入库单；本收货应入数量已确认入库完成，且确认入库数量 &gt; 0 |
| **已退货**   | 无未完成确认入库单；本收货数量已全部由退货等关闭，且确认入库数量 = 0    |

> 来料质检 / 外协回货检列表的「入库状态」：**继续读关联收货单**的入库状态（不另起一套）。

### 2.3 「未完成确认的入库单」定义（与现网对齐）

入库单状态中，下列视为订单/收货侧的 **「入库中」触发源**（即业务口语「待确认」）：

- **待处理**
- **部分入库**（入库单自身行未全部确认完成）

不视为「入库中」触发源：

- **已完成**（全部确认完成）
- **已拒绝 / 已取消** 等无效单据（不计入占用与状态，具体与现网作废规则一致）

## 三、判定规则（订单单列优先级）

对 **采购订单 / 外协订单**，按 **从上到下优先级** 取第一个命中的状态（只展示一列）：

```
1. 存在未完成确认的关联入库单？ → 入库中
2. 整单已闭环 且 已确认入库合计 A = 0？ → 已退货
3. 整单已闭环 且 已确认入库合计 A > 0？ → 已入库
4. 已确认入库数量 A > 0 且未闭环？ → 部分入库
5. 收货数量已覆盖全部订单数量？ → 已收货
6. 收货数量 > 0 且未覆盖全部？ → 部分收货
7. 否则 → 待入库
```

### 3.1 收货进度（用于部分收货 / 已收货）

- **收货数量**：有效收货单明细数量合计（按订单行对齐；作废收货单不计）。
- **已收货**：每一订单行 `收货数量 >= 采购/外协数量`（允许分多次收货累计）。
- **部分收货**：存在行 `0 < 收货数量 < 行数量`，或仅部分行有收货。
- **直连入库、从未收货**：不出现「部分收货/已收货」，只在待入库 / 入库中 / 部分入库 / 已入库 / 已退货间流转（直连场景一般不会已退货，除非后续整单退货关闭且 A=0）。

### 3.2 入库中

- 订单关联的入库单中，任一处于 **待处理** 或 **部分入库** → 订单头 **入库中**。
- 收货单同理：该收货单关联入库单存在上述状态 → 收货单 **入库中**，并触发订单重算（通常亦为入库中）。

### 3.3 闭环、已入库、已退货（含质检不合格 / 退货）

对每一订单行，定义：

| 分量              | 说明                                                                                                                                                                               |
| ----------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| A. 已确认入库数量 | 关联入库单已确认的数量                                                                                                                                                             |
| B. 关闭不可入数量 | 明确不会再入库的数量，至少包括：① 来料/回货质检处置为 **退货** 的数量；② **采购退货 / 外协异常退货** 已生效关闭量（与现网对齐）；③ 质检 **换货** **默认不计入 B**（仍走后续收/入） |
| C. 行需求数量     | 采购数量 / 外协数量                                                                                                                                                                |

**行闭环**：`A + B >= C`（按现网数量精度）。

**整单闭环**：所有行均闭环，且不存在未完成确认的入库单。

在整单闭环前提下：

| 条件                                       | 订单状态   |
| ------------------------------------------ | ---------- |
| 整单 `ΣA = 0`（从未确认入库，全靠 B 关闭） | **已退货** |
| 整单 `ΣA > 0`（至少有一部分已入库）        | **已入库** |

#### 质检不合格退货（明确口径）

1. 质检处置 **退货** 的数量：不要求再入库，计入 **B**。
2. **全退、零入库**（`ΣA = 0` 且整单闭环）：订单 / 对应收货 = **已退货**，**禁止**显示为已入库。
3. **部分入库 + 其余退货**（`ΣA > 0` 且整单闭环）：订单 = **已入库**（有入有退的完成态）。
4. **换货**：不计入 B；占用与后续单据按现有规则。
5. 让步 / 合格入库：确认后计入 A。

> 备注：若后续换货要释放原收货占用，另立占用规则，不在本枚举内再扩状态。

### 3.4 部分入库

- 不存在未完成确认入库单；
- 整单 `ΣA > 0`；
- 未达到整单闭环（故不是已入库 / 已退货）。

## 四、多入口路径（同一状态机）

```
采购订单 ──┬── 直接生成入库单 ──────────────────────▶ 入库单
           ├── 生成收货单 ──▶ 采购收货 ──┬── 生成入库单 ──▶ 入库单
           │                            └── 生成质检 ──▶ 质检完成 ──▶ 生成入库单 ──▶ 入库单
           └──（退货关闭）──▶ 采购退货 …
```

外协订单同构：外协收货 / 外协回货检 / 直接入库 / 异常退货。

| 入口                               | 对订单状态影响           |
| ---------------------------------- | ------------------------ |
| 仅收货未入库                       | 部分收货 / 已收货        |
| 任意入口生成入库单且未全部确认     | **入库中**（覆盖收货态） |
| 入库确认推进                       | 部分入库 / 已入库        |
| 质检 / 退货单 **全退关闭且零入库** | **已退货**               |
| 有确认入库 + 其余退货关闭          | **已入库**               |

## 五、回写与联动时机

以下事件后，必须 **重算** 相关收货单入库状态 + 采购/外协订单入库状态：

1. 创建 / 作废 / 完成收货单
2. 创建 / 取消 / 拒绝 / 确认入库单（整单或按行）
3. 质检提交（回写合格入库数、退货/换货处置）
4. 采购退货 / 外协异常退货生效（影响关闭量 B）

质检列表「入库状态」：只读收货单，收货单更新后自然刷新。

## 六、列表与操作门控（配套）

1. 采购/外协订单列表「入库状态」列：使用 **2.1** 全量枚举与优先级结果。
2. 生成收货 / 生成入库按钮：仍以 **剩余可操作数量** 为准（现有占用规则），状态仅用于展示与筛选，不替代数量校验。
3. 状态为 **已收货** 且剩余可直连入库数量为 0（已被收货占用）时：列表应能看出「已收货」；引导从收货/质检入口入库（建议同期优化禁用提示）。
4. 状态为 **已退货 / 已入库**：按现网完成规则，不再生成收货/入库（与剩余数量=0 一致）。

---

## 七、验收要点

- [ ] 全部收货、未生成入库：订单 = **已收货**（不再误显示待入库）
- [ ] 部分收货：订单 = **部分收货**
- [ ] 收货/质检/订单任一入口生成入库单且待处理：订单与对应收货 = **入库中**
- [ ] 入库单部分确认：有未确认时订单 = **入库中**；全部确认后按数量为部分入库/已入库
- [ ] 全部确认入库：订单 = **已入库**
- [ ] **质检全退、零入库：订单 / 收货 = 已退货（不得为已入库）**
- [ ] 部分确认入库 + 其余退货关闭：订单 = **已入库**
- [ ] 从未收货、直连入库：不出现部分收货/已收货
- [ ] 外协订单 / 外协收货 / 回货检：规则同构通过
- [ ] 列表仍为一列，不新增「收货状态」列

---

## 八、非目标（本需求不做）

- 不拆成「收货状态 + 入库状态」两列
- 不改变入库单内部状态机名称（仍用待处理/部分入库/已完成等）
- 不改变「收货占用与入库申请占用共用采购数量」的数量管控公式（本需求补的是 **头状态展示**）
