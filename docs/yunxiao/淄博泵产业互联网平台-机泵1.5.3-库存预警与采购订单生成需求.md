# 机泵 1.5.3 — 库存预警与采购申请生成采购订单

> 分支：`feat/stock-alert-purchase-order-gen`  
> 范围：产品信息预警字段 + 采购申请→采购订单交互改造 +「半程保存」方案

---

## 一、产品信息 · 预警信息

**场景**：产品信息（及对齐的物料/主数据表单）→「预警信息」Tab。

| 项       | 说明                                               |
| -------- | -------------------------------------------------- |
| 触发     | 打开「库存预警」开关（`stockAlertEnabled = true`） |
| 展示字段 | **最高库存**、**最低库存**（开关关闭时隐藏）       |
| 校验建议 | 开启时两者必填；最低库存 ≤ 最高库存                |

涉及表单：`ProductFormModal` / `MaterialFormModal` / `MasterItemFormModal`（保持一致）。

---

## 二、采购申请 → 生成采购订单

### 2.1 新标签页打开

- 现「生成采购单」弹窗改为**新标签页**页面（与采购申请列表/详情入口对接）。
- 路由建议：`/procurement/purchase-req/generate-po`（query 带申请单 id 列表）。

### 2.2 库存预警列（计划采购量后）

| 条件                                           | 展示                     |
| ---------------------------------------------- | ------------------------ |
| 当前/可用库存（或计划侧对比口径）&lt; 最低库存 | 红色：`低于「最低库存」` |
| 高于最高库存                                   | 蓝色：`高于【最高库存】` |
| 区间内 / 未开启预警                            | `—` 或不展示文案         |

口径需与产品主数据 `alert` 字段及库存取值对齐（实现时固定一种：建议用「可用库存」对比）。

### 2.3 供应商名称

- 支持**边输边搜索**（本地/远程 filter）。
- 支持「选择更多」→ 打开供应商选择弹窗。
- 弹窗内支持**添加供应商**（创建后回填当前行）。

### 2.4 回写默认供应商

- 生成采购订单时：若产品/物料主数据**无默认供应商**，将本行填写的供应商写入默认供应商。
- **已有默认供应商则不覆盖**。

### 2.5 多次生成采购订单（行级状态）

- 一张采购申请可分多次生成采购订单。
- 生成时从本单「移出」的物料行，仍保留在申请中，状态为**未生成采购**，可再次发起。
- 已成功写入采购订单的申请明细行状态为**已生成采购**。
- 申请头状态建议：全部未生成 / 部分生成 / 全部已生成（实现时与现有 `转单` 状态对齐或扩展）。

明细字段新增：`采购状态` = `已生成采购` | `未生成采购`。

## 三、「处理一半先保存」——推荐方案

### 问题

多张采购申请合并生成一张（或多张）采购订单时，物料行很多，用户一次改不完供应商/数量/价格，希望**中途离开、下次接着改**，且不丢已编辑内容。

### 推荐：**采购订单草稿（Draft PO）**（主方案）

把「生成采购单」页本身做成可保存的**草稿采购订单**，而不是只在前端 session 里记状态。

| 能力     | 说明                                                                                                |
| -------- | --------------------------------------------------------------------------------------------------- |
| 保存草稿 | 页内「保存草稿」：落库一张 `status=草稿` 的采购订单，行关联来源申请行 id                            |
| 占用规则 | 草稿行对申请明细打标为「转单中/已占用草稿」（或仍显示未生成，但锁定到该草稿），避免他人重复转同一行 |
| 继续编辑 | 从采购订单列表「草稿」或申请「继续生成」进入同一草稿页                                              |
| 正式提交 | 「确认生成」→ 草稿转正式采购订单；申请行状态改为「已生成采购」                                      |
| 放弃草稿 | 删除/作废草稿 → 释放占用行，申请行恢复「未生成采购」                                                |

**优点**：与现有采购订单模型一致；支持多申请合并；可多人协作看见占用；刷新/关页不丢数据。  
**缺点**：需草稿状态与占用字段；列表要展示草稿。

### 备选 A：生成会话（Session / 处理单）

单独建「采购转单处理单」实体（非 PO），保存勾选行 + 编辑中字段；确认时再拆成正式 PO。

- 适合：转单过程与 PO 字段差异大、或一次会话要拆成多张 PO 再提交。
- 成本高于草稿 PO，一般不必两套都做。

### 备选 B：仅浏览器本地草稿

`localStorage` / IndexedDB 按用户+申请 ids 缓存表格。

- 实现快，但不跨设备、清缓存即丢、无法协作，**不推荐作主方案**（可作弱网兜底）。

### 建议落地节奏

1. **本期**：行级「已生成/未生成」+ 新标签页编辑 + 正式提交时按勾选行生成；页面内「保存草稿」→ 草稿 PO。
2. **交互文案**：按钮「保存草稿」/「生成采购订单」；离开未保存时二次确认。
3. **合并场景**：草稿头记录 `sourceReqIds[]`；行记录 `sourceReqNo + sourceLineId`，保证二次打开可还原勾选与编辑。

### 不推荐

- 把「未提交」只挂在采购申请头上的一个大 JSON：难合并、难审计、难多人。
- 强制用户必须一次全部生成：与「移出可再发起」冲突。

## 四、验收要点（摘要）

1. 库存预警开启后可见最高/最低库存；关闭后隐藏。
2. 生成采购订单在新标签页打开。
3. 计划采购量后预警文案颜色正确。
4. 供应商可搜索、「选择更多」、弹窗内可新增。
5. 无默认供应商时回写；有则不改。
6. 申请明细行状态正确；移出行可再次生成。
7. （若做草稿）保存草稿后关闭页面，再次进入数据不丢；确认后行状态变为已生成采购。
