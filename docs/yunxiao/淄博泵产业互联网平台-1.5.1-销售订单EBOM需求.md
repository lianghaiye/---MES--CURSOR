## SO-151-02 销售订单 EBOM 信息展示与版本对比

- **优先级**：P1
- **需求负责人**：邓利佳
- **验收负责人**：邓利佳
- **需求规划节点**：期初
- **状态**：已实现

**背景**  
自产销售订单审核通过后，系统需为每条标准产品明细生成 **EBOM 快照**（订单初始版本），并据此创建生产计划。产品 BOM 后续可能因 ECN 升版而变更，销售/计划人员需在订单详情中查看 **现行 EBOM**（始终为最新产品 BOM）与 **初始快照** 的差异，评估对在制与交付的影响。原「BOM 版本」Tab 字段口径混乱、对比体验差，且切换全局 Tab 后详情页子 Tab 会丢失。

**目标**  
1. 将 Tab 统一为 **「EBOM 信息」**，清晰展示各明细行的 EBOM 状态与版本信息。  
2. 明确 EBOM 状态语义：**待生成 / 现行 / 已关闭**；现行 EBOM 始终等于最新产品 BOM，暂不做「确认新版本」操作。  
3. 当初始快照版本落后于现行版本时，展示 **版本变更** 区块及差异对比（内联 + 弹窗并排对比）。  
4. 修复详情页 Tab 在全局页签切换后的 **持久化** 问题。

---

### 一、业务逻辑（EBOM 快照生成）

#### 1.1 新建销售订单

- 业务类型为 **自产销售** 的标准产品明细：新建时自动带入产品 **当前生效 BOM**（`bomId`、`bomName`、`bomVersion`）。
- **定制产品** 明细：不绑定 BOM，审核后走设计任务流程，本需求不涉及定制 EBOM 设计页。

#### 1.2 审核通过

对标准产品明细执行：

1. 校验产品存在 **使用中的 BOM**，否则审核失败并提示。
2. 写入明细行 `bomId` / `bomName` / `bomVersion`（若尚未绑定）。
3. 按销售数量调用 `buildEbomSnapshotFromBom` 生成 **`ebomSnapshot`**（含物料树、版本号、快照时间等）。
4. 同步创建生产计划任务（与生产计划模块联动，不在本 Tab UI 范围）。

#### 1.3 现行 EBOM 定义

- **现行 EBOM** = 产品当前 **生效 BOM 的最新版本**（含 ECN 升版后）。
- 不做「确认新版本」：订单侧不维护独立的「待确认/已确认」状态。
- **已关闭**：关联工单/计划完结后标记（预留字段 `ebomStatus = 已关闭`），不再用于在制。

### 三、EBOM 信息列表

按销售订单 **明细行** 逐行展示，数据源 `buildSalesOrderEbomRows`：

| 列名 | 说明 |
|------|------|
| 序号 | 明细行序号 |
| EBOM状态 | 待生成 / 现行 / 已关闭，带颜色标签 |
| EBOM名称 | 可点击跳转产品 BOM 详情 |
| EBOM编码 | |
| 产品名称 | |
| **初始版本** | 订单审核通过时的快照版本（`bomVersion` / `ebomSnapshot.bomVersion`） |
| **订单绑定版本** | 当前最新 EBOM 版本（现行产品 BOM 版本） |
| 规格型号 | |
| 材质 | |
| 图号 | |
| 层级数 | 来自最新 BOM 展开 |
| 物料数 | 来自最新 BOM 或快照 |
| 快照时间 | 审核生成快照的时间 |

**EBOM 状态规则**（`resolveEbomSnapshotStatus`）：

| 状态 | 条件 | 标签色 |
|------|------|--------|
| 待生成 | 无 `bomVersion` 且无快照物料 | default |
| 现行 | 已有快照，且未标记已关闭 | success |
| 已关闭 | `ebomStatus === '已关闭'` | default |

**数据规则**：

- 列表 **现行字段**（名称、编码、规格、层级、物料数、订单绑定版本）均取 **当前生效产品 BOM** 最新数据。
- **初始版本 / 快照时间** 取订单明细上的快照字段，不随 ECN 变更而改写。

### 四、EBOM 版本变更区块

**展示条件**：明细行存在 `productId`，且 **初始版本 ≠ 当前生效 BOM 版本**。

每个有变更的明细行展示一块卡片，包含：

1. **行头**：产品名称、产品编码、初始版本 Tag（橙色）、现行版本 Tag（蓝色）。
2. **BomVersionInfoSection**：
   - 最新 BOM 名称、版本、状态（产品 BOM 档案「生效」展示为 **「现行」**）。
   - 绑定版本提示：「绑定版本：X · 当前已升级至 Y」。
   - **版本变更记录** 时间线（ECN 升版历史），支持查看 BOM、版本对比。
3. **SalesOrderEbomDiffSection**（EBOM 差异对比）：
   - 标题：初始版本 → 现行版本。
   - 摘要 Tag：新增 / 修改 / **替换** / 删除 数量；无结构变化时提示「物料结构无变化，仅 BOM 版本号已升级」。
   - 内联 **差异清单表格**（`EbomDiffTable`）。
   - **「弹窗对比」** 按钮，打开 `BomVersionCompareModal`。

**已移除**：版本变更区块顶部的蓝色 `a-alert` 提示条。

### 五、EBOM 差异对比算法

#### 5.1 对比基准

- **旧侧**：订单明细 `ebomSnapshot`（审核时按销售数量展开）。
- **新侧**：当前生效 BOM 按相同销售数量重新展开（`buildEbomSnapshotFromBom`）。

#### 5.2 变更类型

| 类型 | 识别规则 | 展示色 |
|------|----------|--------|
| 新增 | 新快照有、旧快照无 | success |
| 删除 | 旧快照有、新快照无 | error |
| 修改 | 同路径物料字段变化 | warning |
| **替换** | 同父级下「删除 + 新增」成对出现，合并为一行 | purple |

对比字段：物料名称、规格型号、材质、单位用量、单位、供应形态、需求数量、工艺路线。

#### 5.3 弹窗对比（BomVersionCompareModal）

| 项 | 说明 |
|----|------|
| 弹窗宽度 | **1400px**（最大 96vw） |
| Tab · 差异清单 | 路径级差异表格 + 汇总 Tag |
| Tab · 并排对比 | 按 **BOM 树结构位置**（层级 + 同级序号）左右对照 |
| 换料展示 | 同位置编码、名称均变 → 同一行「原物料 ⇄ 新物料」，紫色底色 |
| 数量 | 标题/元信息展示「按数量 N 展开」（取销售数量） |

### 六、Tab 持久化

**问题**：通过 GlobalTabs 切回销售订单详情时 URL 不带 `?tab=`，且原 `fullPath` 作 router key 导致组件重挂载，子 Tab 回到「概览」。

**方案**：

1. `MainLayout`：`router-view` 的 `:key` 改为 **`route.path`**（同路径 query 变化不重挂载）。
2. `salesOrderDetailTab.js`：`sessionStorage` 按订单 ID 缓存当前 Tab。
3. `SalesOrderDetailView`：`onActivated` + `watch(route.query.tab)` 恢复 Tab；无 query 时读缓存，**不强制重置为概览**。
4. 切换 Tab 时同步写入 URL query（非 overview 时带 `?tab=`）与 sessionStorage。

### 七、与周边模块关系

| 模块 | 关系 |
|------|------|
| 产品 BOM | 现行 EBOM 来源；列表/对比均引用 `getActiveBomForItem` |
| ECN 工程变更 | BOM 升版后触发版本差异；时间线来自 ECN 版本历史 |
| 生产计划 | 审核快照用于计划物料展开；计划页 EBOM 树另见生产计划需求 |
| 设计任务 | 定制产品明细不走 EBOM 快照，审核后创建设计任务 |

- [ ] Tab 名称为「EBOM 信息」，key 为 `ebom-info`，旧 `bom-version` 链接可正常打开

- [ ] EBOM 列表字段与第三节一致；EBOM 状态为待生成/现行/已关闭
- [ ] **初始版本** 为审核快照版本；**订单绑定版本** 为当前最新 BOM 版本
- [ ] EBOM 名称可跳转产品 BOM 详情页
- [ ] 初始版本 ≠ 现行版本时展示「EBOM 版本变更」区块（含差异摘要、内联表格、弹窗对比）
- [ ] 差异对比支持新增/修改/删除/**替换** 四类；同父级换料合并为「替换」
- [ ] 弹窗并排对比按 BOM 树结构位置对齐，换料同一行左右展示

- [ ] 审核通过时标准明细正确生成 `ebomSnapshot`；无 BOM 产品时审核拦截
