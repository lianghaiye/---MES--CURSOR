# 采购对账 · 退货与生成维度规则（云效需求说明稿）

> 用途：建云效需求 / 评审时直接粘贴或引用本节。实现代码：`purchaseSettleStore` + `utils/purchaseSettleReturn.js`。

---

## 1. 术语

| 术语                        | 含义                                                                                   |
| --------------------------- | -------------------------------------------------------------------------------------- |
| 生成维度·按入库             | 按入库业务日落入账期窗扫描可结入库行生成对账单                                         |
| 生成维度·按采购单（已完成） | 仅扫描「已完成」采购单；明细仍来自该单可结入库行 + 可红冲退货行                        |
| 未入库退货                  | 货未入仓即退；确认后完成、**不出库**；只关闭采购开口                                   |
| 已入库退货 / 出库退货       | 已入仓后退货；须出库完成；**应对账红冲（数量为负）**                                   |
| 追加未结算量                | 同供应商同账期已有对账单时，仍扫描「剩余可结量 &gt; 0」的入库/退货并生成（可新开一张） |
| 占量                        | 草稿对账单即占用可结量，防止多规则/多次生成重复出单                                    |

---

## 2. 总原则

1. **未入库退货不进对账单**（无红冲行）。只参与采购订单自然结清：`入库数量 + 已完成未入库退货 ≥ 采购数量`。
2. **已入库退货且出库完成** → 对账单出现来源=「退货」的明细，**来源单号=退货单号**，结算数量为负，金额红冲。
3. 入库行剩余可结量 / 退货行剩余可红冲量 = 0 时，**追加扫不到**（已确认占用 + 草稿占用）。
4. 明细「来源」展示：
   - 按入库生成的入库行 → **入库**
   - 按完成采购单生成的入库行 → **采购**
   - 退货红冲行 → **退货**（与生成维度无关）
5. 单据日期：入库行取入库日；退货行取出库日（无出库单时用退货完成/确认日兜底，仅未入库场景，正常不入账）。

## 3. 场景矩阵（验收用例）

### 3.1 按入库维度

| #   | 前置            | 操作                                                  | 期望                                                           |
| --- | --------------- | ----------------------------------------------------- | -------------------------------------------------------------- |
| A1  | 采购 10，入库 5 | 账期生成                                              | 对账结 **5**                                                   |
| A2  | A1 已确认后     | 未入库退货 5 → 订单自然完成；勾选「追加未结算量」再扫 | **扫不到**该单（入库已结完；未入库退货不产生对账行）           |
| A3  | A1 已确认后     | 出库退货 2（已入库退货出库完成）                      | 追加/下期扫到红冲行，数量 **−2**，来源=退货，来源单号=退货单号 |

### 3.2 按采购单（已完成）维度

| #   | 前置                                                  | 操作               | 期望                                                  |
| --- | ----------------------------------------------------- | ------------------ | ----------------------------------------------------- |
| B1  | 采购 10，入库 5，订单未完成                           | 按完成采购单扫账期 | **扫不到**                                            |
| B2  | B1 后做未入库退货 5 → 订单完成                        | 再扫               | 扫到该单，按可结入库 **结 5**；**无**未入库退货红冲行 |
| B3  | 采购 10，入库 5，仅出库退货 2（无未入库退货、未短结） | 再扫               | 净入库不足采购，**不会自动完成** → **仍扫不到**       |
| B4  | 订单已完成（自然结清或短结），且存在未入账的出库退货  | 生成/追加          | 对账单含入库正数行 + 退货红冲行（如 −2）              |

## 4. 生成与占量（实现要点）

### 4.1 可扫入库行

- 入库行状态=已入库，且 `剩余可结量 = 可结总量 − 已确认 − 草稿占用 > 0`
- 按入库：入库日 ∈ 账期窗
- 按采购单：采购单 status=已完成，完成日 ∈ 账期窗（手工按单生成不强制完成日窗时仍要求已完成）

### 4.2 可扫退货红冲行

- 退货类型=已入库退货
- 退货单已完成（或出库状态=已出库）
- `剩余可红冲量 = 已入库退货数量 − 行上 settledSettleQty − 草稿占用 > 0`
- 按入库：退货业务日（优先出库日）∈ 账期窗
- 按采购单：挂在该已完成采购单下即可（与完成日同窗扫单时一并带出）

### 4.3 落库字段（明细行）

- `sourceType`: `inbound` | `purchase` | `return`
- 退货行必填：`returnOrderId` / `returnOrderNo` / `returnLineId`；建议带 `outboundOrderId` / `outboundDocNo`
- `settleQty`：入库为正，退货为负

### 4.4 确认对账

- 入库行：累加 `inboundLine.settledSettleQty`
- 退货行：累加 `returnLine.settledSettleQty`（按绝对值）

## 5. 行级争议挂起（差额 / 整笔，不阻断确认）

> 两种性质：
>
> - **差额**：填对方主张，系统算差；**挂起时确认额仍按账面**，核销后再改。
> - **整笔**：整行先不付，**挂起时行确认额=0**，核销后再按结论计入。  
>   登记同步「争议挂账」；供应商往来见「往来结算 → 供应商往来」。

| 步骤      | 说明                                             |
| --------- | ------------------------------------------------ |
| 登记      | 选性质；差额必填对方主张；整笔主张可选           |
| 确认/付款 | **允许**：确认金额 = Σ行确认额；不挡确认与付款   |
| 核销      | 采纳我方/取消→账面；采纳对方→主张；折中→谈妥金额 |
| 挂出金额  | 差额=‖主张−账面‖；整笔=‖行金额‖                  |

## 6. 云效需求标题/描述建议

**标题示例：**  
`【采购对账】出库退货红冲入账；未入库退货不入对账；追加按剩余可结量扫描`

**描述可粘贴：**  
本节 §2～§4。验收以 §3 场景矩阵 A1–A3、B1–B4 为准。

**已支持补充：**  
确认后反确认（未开票/未付款）、打印/导出给供应商、对账单内费用补差行（运费/尾差/调价补差）。

**非目标（可单开需求）：**  
采购折让/索赔专单、预付款冲抵、期初未结转入。
