# 操作手册 · 快速入门（手把手）

> 适合：第一次打开 I-DOMS 的人。读完并跟着做一遍，应能完成「报一笔工 → 审一笔 →（按配置）看到工资」的最小闭环。

---

## 0. 先搞清楚两件事

### 0.1 电脑端和手机端分别干什么？

| 端             | 你通常用它做什么                                                | 打开方式                       |
| -------------- | --------------------------------------------------------------- | ------------------------------ |
| **电脑 Web**   | 建产品/工序、开工单、审核报工、推送工资、出入库确认、改系统参数 | 浏览器打开公司提供的网址并登录 |
| **微信小程序** | 工人领任务、报工、看自己的工时工资；现场领料/成品入库/质检填报  | 微信里打开企业小程序并登录     |

一句话：**现场干活用手机，开单审核用电脑。**

### 0.2 你的角色是哪一种？

先对号入座，再跳到对应章节，不要从头硬读全部：

| 我是…             | 请读                            | 第一天目标                                       |
| ----------------- | ------------------------------- | ------------------------------------------------ |
| 工人 / 操作工     | [§3](#3-工人第一天手把手)       | 手机成功提交 1 笔报工                            |
| 车间主任 / 班组长 | [§4](#4-车间主任第一天手把手)   | 电脑审核通过 1 笔报工                            |
| 仓管              | [§5](#5-仓管第一天手把手)       | 会找出入库菜单，知道小程序领料入库后要在电脑确认 |
| 管理员 / 实施     | [§6](#6-管理员实施第一天手把手) | 主数据+生产模式+工资推送配好，能支撑试点         |

## 1. 登录与界面认路（电脑 Web）

### 1.1 登录

1. 用浏览器打开管理员给你的地址（示例演示站可能是 `https://zb.mes.iipcloud.com/login`，**以你们现场为准**）。
2. 输入账号、密码 → 登录。
3. 若进不去：检查网络、账号是否启用、是否进错测试/正式环境；仍不行找管理员重置密码。

### 1.2 认识顶栏（一级模块）

登录后，页面**最上方一排**是模块切换，常见有：

首页｜产品工艺｜销售管理｜计划排产｜生产管理｜报工管理｜工时工资｜库存管理｜质量管理｜采购管理｜外协管理｜工程变更｜工业标识｜基础配置｜系统管理

- **点哪个顶栏**，左侧就会出现该模块的子菜单。
- 看不到某个顶栏：多半是角色没授权，不是系统坏了。

### 1.3 认识左侧菜单与内容区

1. 点顶栏 **报工管理**。
2. 左侧应出现：报工确认、工序报工、工资核算、核算详情 等。
3. 点 **工序报工**：中间大区域就是列表（可筛选、可点行进详情）。

### 1.4 找不到功能时怎么查

1. 先确认顶栏有没有对应模块。
2. 再在左侧子菜单里找中文名称。
3. 仍没有 → 找管理员开权限 / 确认公司是否购买了该场景模块。

## 2. 小程序认路

1. 微信打开企业小程序 → 登录（账号需与电脑人员档案绑定）。
2. 底部一般有 **工作台** / **我的**。
3. 工作台常见入口卡片：
   - **工序报工**（工人必用）
   - **工时工资**（看自己钱）
   - **报工确认**（通常只有主任看得见）
   - 领料管理、成品入库、质检任务、盘点管理（按场景开通）
4. 某个入口没有：找管理员查角色或场景是否开通。

## 3. 工人第一天（手把手）

> 目标：用手机成功提交 1 笔报工。  
> 前提：管理员已建好「产品 + 工序 +（任务报工时）工单已下发」。

### 3.1 先问主任一句话

问清楚你们厂用的是哪一种：

| 说法         | 你在小程序里怎么走                         |
| ------------ | ------------------------------------------ |
| **任务报工** | 必须先「待领」领取，再到「今日待报工」填数 |
| **快速报工** | 直接进「快速报工」，自己选产品/工序填数    |

不确定就先看小程序 **工序报工** 里有没有「快速报工」Tab；没有就按任务报工做。

### 3.2 任务报工：一步一步点

1. 打开小程序 → **工作台** → 点 **工序报工**。
2. 顶部切到 **待领任务**（或文案类似「待领」）。
3. 找到主任下发的任务 → 点进去 → 点 **领取任务**。
   - 成功一般有「领取成功」提示，并跳到待报工列表。
4. 切到 **今日待报工** → 点该任务的 **去报工**。
5. 在填写页按实际填写：
   - 看清顶部的 **排产数量 / 待报工数量**（报多了系统会拦）。
   - **批量计件**：填 **良品数量**（必填）；若有不良，填不良数，并按不良原因把数量分摊完。
   - **时长报工**：填 **工作时长（小时）**；这类一般只能算计时工资。
   - 确认 **执行人** 是自己（代报时按厂规选人）。
   - 需要时可拍照上传现场图片、写备注。
6. 点 **提交报工**。
7. 到 **我的记录**（若有）确认状态为 **待审核**。

### 3.3 快速报工：一步一步点

1. 工序报工 → Tab **快速报工**。
2. 点 **+ 新增快速报工**（或点最近常报工序）。
3. 选择 **产品** → 选择 **工序**。
4. 填写良品/不良等 → **提交报工**。

### 3.4 报完以后工资什么时候能看见？

打开 **工时工资**：

- 若是空的，**不一定报错了**。常见原因：
  1. 主任还没审核；
  2. 公司设置成「手动推送」，还没人点推送；
  3. 设置成「审核后推送」，但审核还没过。
- 先问主任：「我们工资是报工就看见、审完才看见，还是要财务推送才看见？」

### 3.5 工人常见卡点

| 你看到的提示/现象         | 你该怎么做                              |
| ------------------------- | --------------------------------------- |
| 请先领取任务后再报工      | 回「待领」先领取                        |
| 报工数量不能超过待报 n 件 | 少报一点；或确认是否重复报              |
| 请分配全部不良原因        | 把不良数量按原因分摊完，加起来=不良总数 |
| 没有待领任务              | 问主任工单是否已下发、是否派到你        |
| 没有快速报工入口          | 公司可能关掉了快速报工，改用任务报工    |
| 工时工资一直空            | 问推送模式；不是手机坏了                |

## 4. 车间主任第一天（手把手）

> 目标：在电脑上把工人刚报的那笔审过去。

### 4.1 审核工序报工

1. 电脑登录 → 顶栏点 **报工管理**。
2. 左侧点 **工序报工**。
3. 筛选状态选 **待审核**（也可按报工方式筛：任务报工 / 快速报工）。
4. 点开一条记录，核对：
   - 产品、工序、良品/不良、报工人、时间是否合理。
5. 没问题 → 点 **通过**（列表也常有 **批量通过**）。
6. 有问题 → 点 **拒绝**，**必须填写拒绝原因**（工人才能知道怎么重报）。

注意：

- **已审核** 的记录一般不能再拒绝、不能再改数量/单价。
- 审之前想改数，优先用 **报工确认**（见下）或按你们厂《计薪口径》约定。

### 4.2 报工确认（调整 / 补贴 / 推送确认）

1. 左侧点 **报工确认**。
2. 看上方状态：待确认 / 待工人确认 / 已确认。
3. 对需要改的任务点 **调整**（良品、不良、工时、补贴等——以页面字段和厂规为准）。
4. 需要工人再确一下时，点 **推送确认**。

### 4.3 工资怎么让工人看见（手动推送时）

先问管理员当前是哪种 **工资推送模式**（系统管理 → 功能参数）：

| 模式       | 主任要做什么                                             |
| ---------- | -------------------------------------------------------- |
| 报工即推送 | 通常不用额外推送                                         |
| 审核后推送 | 你把报工 **审核通过** 即可                               |
| 手动推送   | 审核后还要到 **工资核算 / 工时管理** 勾选明细点 **推送** |

手动推送示例：

1. 报工管理 → **工资核算** 或 工时工资 → **工时管理**。
2. 核对员工、金额是否合理。
3. 勾选待推送明细 → **推送** / **批量推送**。
4. 让工人刷新小程序「工时工资」查看。

### 4.4 若你们已用工单（场景三）

1. 顶栏 **生产管理** → **生产工单**。
2. 找到 **待下发** 工单 → 勾选 → **批量下发**（或单笔下发）。
3. 告诉工人：去小程序「待领」领取后再报。

## 5. 仓管第一天（手把手）

> 场景二及以上才需要。第一天目标：知道料从哪出、货从哪进、小程序提交后你要在哪点确认。

### 5.1 先确认仓库建好了没有

1. 顶栏 **基础配置** → **仓库管理** → **仓库列表**。
2. 建议至少有：
   - 原料仓 / 发料仓
   - 线边仓（车间现场暂存）
   - 成品仓
3. 没有就先让管理员建（见《11-系统管理与基础配置》）。

### 5.2 领料之后你在哪操作？

1. 工人/班组可能在小程序点了领料；或主任在 **生产管理 → 领料管理** 申请了领料。
2. 若公司没开「领料申请自动审批」，你要在领料列表里 **通过**。
3. 再到 **库存管理 → 待出库列表 / 出库管理**：
   - 打开单据 → 核对仓库与数量 → **确认出库**（或保存并出库）。

### 5.3 成品入库之后你在哪操作？

1. 现场小程序提交成品入库后，电脑 **库存管理 → 待入库列表 / 入库管理** 会出现单据（常显示待入库/待审批）。
2. 打开 → 核对仓库数量 → **确认入库**。
3. 若管理员开了「成品入库自动审批」，可能免这一步。

### 5.4 盘点注意

小程序可以录入实盘并提交，但页面会提示类似「已提交，请到 PC 审核」。  
**审核和过账只在电脑「库存管理 → 盘点管理」做。**

## 6. 管理员实施第一天（手把手）

> 目标：支撑「一个班组试点报工+工资」。不要第一天就开全模块自动生成。

### 6.1 必做顺序（照着勾）

| 顺序 | 做什么                                       | 在哪里                  |
| ---- | -------------------------------------------- | ----------------------- |
| 1    | 确认试点范围（先场景一：报工+工资）          | 与客户书面确认          |
| 2    | 签《计薪口径确认表》                         | 实施附件                |
| 3    | 建人员 / 员工组别，绑定小程序账号            | 组织人员 + 基础配置     |
| 4    | 建 3～5 个试点产品，填供应型态、单位、规格   | 产品工艺 → 产品信息     |
| 5    | 建工序；配工时/工价（按口径）                | 工序配置 + 产品工时配置 |
| 6    | 建工艺路线并挂到产品默认路线（任务报工需要） | 工艺路线                |
| 7    | 设生产模式                                   | 系统管理 → 业务规则     |
| 8    | 设工资推送模式                               | 系统管理 → 功能参数     |
| 9    | 给主任/工人开对菜单权限                      | 角色权限                |
| 10   | 带 1 个工人 + 1 个主任现场走通一笔           | 小程序 + Web            |

### 6.2 生产模式怎么选（白话）

| 现场习惯                     | 业务规则建议                    |
| ---------------------------- | ------------------------------- |
| 先不要工单，工人自己选工序报 | 极简报工 → **快速报工**         |
| 必须先有工单任务再报         | 标准模式，或极简 → **任务报工** |

路径：顶栏 **系统管理** → **业务规则** → 找到「生产模式」→ 选择 → 保存。

### 6.3 工资推送怎么选（白话）

路径：顶栏 **系统管理** → **功能参数** → 分类里找「生产与计划」或页面中的 **工资推送**。

| 选项       | 适合                             |
| ---------- | -------------------------------- |
| 报工即推送 | 想让工人马上看见（争议风险更高） |
| 审核后推送 | 多数试点推荐                     |
| 手动推送   | 财务要再卡一道（默认常见）       |

### 6.4 第一天验收标准（场景一）

| 检查项   | 怎样算通过                                   |
| -------- | -------------------------------------------- |
| 工人报工 | 小程序提交成功，Web 工序报工能看到待审核     |
| 主任审核 | 能通过/拒绝（拒绝能填原因）                  |
| 工资可见 | 按所选推送模式，工人或核算列表能看到对应明细 |
| 口径一致 | 金额算法与签字口径一致                       |

## 7. 推荐学习路径（别一次学完）

```
第1天  快速入门（本文）+ 小程序报工
第2天  产品工艺：会建产品、工序、路线、工价
第3天  生产工单下发 + Web 审核报工 + 工资推送
第4天  （若上库存）领料、入库、仓库
第5天  （若上订单）销售订单 → 计划 → 工单样例
```

详细步骤请继续阅读同目录下各模块手册（02～11）。

## 8. 全局常见问题（入门向）

| 现象                 | 处理                                           |
| -------------------- | ---------------------------------------------- |
| 顶栏菜单很少/是空的  | 角色或产品包未授权                             |
| 小程序没有报工       | 未绑定账号 / 未开通入口 / 生产模式未开对应报工 |
| 选不到产品           | 产品未建、已归档、或无权限                     |
| 审核后工人仍无工资   | 多半是「手动推送」还没推                       |
| 演示环境数据隔天乱了 | 演示可能用本地缓存；培训请用正式/稳定环境      |
