# I-DOMS MES · AI 智能问答 Agent 素材库

| 项目     | 内容                                                                                          |
| -------- | --------------------------------------------------------------------------------------------- |
| 产品     | I-DOMS（离散制造 MES，对外品牌可称「泵小智」）                                                |
| 形态     | WEB + 微信小程序                                                                              |
| 用途     | 为本系统 AI 智能问答 Agent 提供可检索的 Markdown 知识素材                                     |
| 版本基准 | 与 `i-doms-web` / `i-doms-mobile` 当前实现及 `docs/implementation` 实施手册对齐（2026-09/10） |
| 维护原则 | 以菜单路径、功能参数键值、状态名为准；口头别名需对照本文纠正                                  |

## 1. 目录结构

```
ai-agent-kb/
├── README.md                 ← 本索引（Agent 检索入口）
├── agent/                    ← System Prompt（可直接粘贴）
├── structured/               ← 菜单树/状态边/参数/错误码 JSON
├── reference/                ← 系统地图、参数、术语、状态机
├── manuals/                  ← 分模块操作手册
├── faq/                      ← 客户 FAQ + 实施 FAQ
├── errors/                   ← 报错信息库（现象→原因→处理）
└── processes/                ← 端到端流程文档
```

| 目录          | 给 Agent 的用途                    | 典型用户问法                             |
| ------------- | ---------------------------------- | ---------------------------------------- |
| `agent/`      | System Prompt / Few-shot / 评测题  | （工程配置，非用户问）                   |
| `structured/` | 精确匹配：菜单、状态、参数、错误码 | 「能不能发货」「参数取值」               |
| `reference/`  | 先定位模块/参数/术语               | 「工资推送在哪配」「库存扣减是什么意思」 |
| `manuals/`    | 逐步操作指导                       | 「怎么开销售订单」「小程序怎么报工」     |
| `faq/`        | 高频答疑、口径统一                 | 「为什么工资看不到」「实施先上哪个场景」 |
| `errors/`     | 按报错原文匹配                     | 「提示库存不足怎么办」                   |
| `processes/`  | 跨模块链路说明                     | 「从接单到发货怎么走」                   |

## 3. 快速接入（工程）

1. 将 [agent/SYSTEM_PROMPT.md](./agent/SYSTEM_PROMPT.md) 中「可复制 Prompt」设为系统提示词。
2. 按 [structured/ingest-manifest.json](./structured/ingest-manifest.json) 导入语料（P0→P2）。
3. 报错优先走 `error-codes.json` 精确/模糊匹配，再补检索 Markdown。
4. 上线前跑完 SYSTEM_PROMPT 内 10 道评测题。

## 4. Agent 检索建议

1. **先识别意图**：操作步骤 / 概念解释 / 报错排查 / 流程串联 / 实施选型。
2. **再定位域**：报工工资、库存领料、销售计划、采购外协、质量、系统参数。
3. **优先匹配**：
   - 报错原文 → `structured/error-codes.json` / `errors/`
   - 「怎么做」→ `manuals/`
   - 「为什么 / 能不能」→ `faq/` + `status-edges.json`
   - 「从 A 到 B」→ `processes/`
   - 「在哪配置」→ `function-params.json` / `reference/01`
4. **回答规范**：
   - 给出 **菜单路径**（如：系统管理 → 功能参数 → 工资推送）。
   - 区分 **对外话术** 与 **对内配置**（尤其「库存扣减」不对客作卖点）。
   - 不确定是否已上线的能力标明「以现场版本/功能参数为准」。
5. **客户端识别**（打印相关）：I-DOMS 以浏览器打印为主；若现场日志出现 `print_client_service`，属智衣 OMS 打印客户端，勿与本 MES Web 打印或 `mes_print_client_service` 混淆。

## 5. 五场景速记（Agent 选型用）

| 编码 | 对外场景                      | 一句话               |
| ---- | ----------------------------- | -------------------- |
| 一   | 快速报工 + 工资核算           | 手机报工，工资算得出 |
| 二   | 一 + 领料 + 成品入库          | 料出、货进留单       |
| 三   | 任务报工 + 工资 + 领料 + 入库 | 工单任务约束         |
| 四   | 订单→BOM→计划→生产→库存→采购  | 接单到采购闭环       |
| 五   | 四 + 质量管理                 | 出厂检/报废留痕      |

详情见 [P06-五场景选型与扩场景.md](./processes/P06-五场景选型与扩场景.md)。

## 6. 维护约定

- 功能参数、状态名变更时，同步改 `reference/`、`errors/` 与 `structured/*.json`。
- 新增菜单时更新 `reference/00-系统总览与模块地图.md` 与 `structured/menu-tree.json`。
- 客户现场踩坑沉淀进 `faq/`，报错原文进 `errors/` 与 `structured/error-codes.json`。
- 不在本库粘贴合同、密钥、客户隐私数据。
