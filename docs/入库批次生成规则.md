# 入库批次生成规则

确认入库时生成库存批次（及按件填写时的 SN 件码）。实现入口：`confirmInboundOrders` / `confirmInboundLine` → `prepareAndApplyInboundLine` → `applyInboundBatchesFromRoots`。

## 1. 批次号

格式：`B-YYMMDD-流水`，流水 3 位（001–999）。

- 按**入库时间**取日：`B-260901-001`
- 同日已有批次取最大序号 +1；兼容历史 2 位流水
- 实现：`generateBatchNo`（`src/store/stockBatchStore.js`）

件码号：`{批次号}-{4位SN}`，如 `B-260901-001-0001`。

一物一码始终按件赋 SN。一类/一批一码在采购单位≠库存单位且填写「统一单件 / 逐件」时，同样 1 个父批 + 四位 SN；填「直接填合计」则只有父批、无 SN。

## 2. 何时建批

仅 **确认入库** 时建批（整单或按明细）。保存草稿、待处理入库单不生成批次。

成品/半成品入库须先能解析到销售订单；再按销售行未满足量把 `pieceValues` 切成「按单批次」与「自由备货批次」。

## 3. 一条入库明细生成几批

先把明细展开成 `pieceValues[]`（每个元素 = 一件的**库存单位**数量），再按条码类型与填写方式建批。

### 3.1 如何得到 pieceValues

| 物料                | 填写方式   | pieceValues                                     |
| ------------------- | ---------- | ----------------------------------------------- |
| 双单位 / 可变长     | 统一单件   | `采购数量` 个相同值（`uniformValue`）           |
| 双单位 / 可变长     | 逐件       | `pieceValues` / `pieceLengths` / `pieceWeights` |
| 双单位 / 可变长     | 直接填合计 | 仅一类一码 / 一批一码允许；一物一码禁止         |
| 非可变长 + 一物一码 | 按件数     | `round(qty)` 个 `1`（每件 1 个库存单位）        |
| 非可变长 + 其他条码 | 合计       | `[qty]` 一个元素                                |

一物一码禁止「直接填合计」合批，必须统一单件或逐件。

### 3.2 条码类型 × 填写方式 → 批次结构

**一物一码**

- 禁止「直接填合计」
- **1 个父批次**（库存账，`currentLength` = 各件合计）+ **N 条件码**
- 件码 = `{批次号}-{四位SN}`（0001 起）
- 父批 `attrs.manageByPiece = true`，`attrs.pieceCount = N`

**一类一码 / 一批一码，且采购单位 ≠ 库存单位**

| 填写方式                | 结果                                          |
| ----------------------- | --------------------------------------------- |
| 直接填合计              | **1 个批次**，不合件码、无 SN                 |
| 统一单件数量 / 逐件数量 | 与一物一码相同：**1 父批 + N 个四位 SN 件码** |

**一类一码 / 一批一码，采购单位 = 库存单位**

- 按合计数量生成 **1 个批次**，无件码

库存明细可展开查看带件码的批次。

## 4. 批次上带什么

| 字段                              | 含义                                                       |
| --------------------------------- | ---------------------------------------------------------- |
| `warehouse` / `itemCode` / `unit` | 仓库、物料、**库存单位**                                   |
| `inboundQty`                      | 入库库存量：本批建账库存量（库存单位，出库不扣；期初亦然） |
| `inboundPurchaseQty`              | 有采购单位差时：本批建账采购量（采购单位点收，出库不扣）   |
| `currentLength`                   | 在库数量（当前余量；历史字段名，长度/面积/重量/件数通用）  |
| `sourceType` / `sourceDocNo`      | 来源类型（采购入库等）、入库单号                           |
| `salesOrderId` 等                 | 成品/半成品按单入库时的销售单血缘                          |
| `uomConvert`                      | 有结算单位时：结算换算快照（不写回主数据）                 |
| `attrs.barcodeType`               | 条码类型                                                   |
| `attrs.inboundEntryMode`          | uniform / piece / total                                    |

### 结算单位（uomConvert）

入库行同时有 `settleUnit` + `settleQty` 时写入批次：

- `pieceCount`：本批入库时的点收量（采购到货、成品/半成品缴库都用这一列），**出库不扣**；界面有采购单位差时记在「入库数量」，不再单独叫「入库件数」
- `purchaseUnit`：点收/入库数量的单位（采购单位或缴库计数单位，如根/张/件）
- `settleQty`：本批结算数量（结算单位，如 kg / ㎡，不限定重量）
- `actualUnitWeight` = settleQty / pieceCount（界面「批次单量」，供下次开单预估）
- 一行拆多批时按库存量占比分摊

采购单位本身不落在库存账上：库存只记库存单位。有采购≠库存时，点收量写入 `inboundPurchaseQty`，库存建账量写入 `inboundQty`。

## 5. 出库与余料（影响库存明细看到的批/件）

功能参数两条要一起看：出库拣批顺序 × 下料结算发料方式。

### 5.1 普通料（未勾「需要下料结算」）

按出库数量扣，余量留原批。一物一码优先整件凑齐；凑不齐则拆件：原件码整件核销，余量生成**新件码**（仍挂原父批，`remnant: true`）。

### 5.2 需下料结算 +「部分出+余料留原批」

扣账合计 = 出库数量，不因整根多扣。余量留原批（一物一码同上可拆件码）。

### 5.3 需下料结算 +「整批出+下料结算回库」

整件/整批离开发料仓，实发可大于需求。领入线边后由**下料结算**填实耗：

- 从线边扣掉领入量
- 余料 > 0 则 `receiveRemnantBatch`：**新批次号**，`parentBatchId` 指向原批，`attrs.remnant`，来源「余料入库」，并生成余料入库单

## 6. 库存明细怎么看

- **库存台账**：按仓+料汇总（批次 `currentLength` 之和）
- **查看批次**：父批列表，列随物料单位口径变化。
  - 只有库存单位：在库数量、入库数量（均为库存单位；入库=建账量，在库=余量）
  - 采购≠库存：在库数量（库存单位）、入库数量（采购单位点收）、**入库库存量**（建账时折成库存单位的量）
  - 有结算单位：再加结算数量、批次单量
  - **凡带件码的批次均可展开**（一物一码；以及一类/一批一码在采购≠库存且按统一单件/逐件入库的）。填合计的一类/一批只有父批、无展开。
- **物料流水**：入库来自批次建档，出库来自出库单 `batchAllocations`（含件码）；件码出库痕迹会补进流水
